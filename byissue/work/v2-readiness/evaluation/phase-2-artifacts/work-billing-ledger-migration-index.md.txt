# 账单迁移工具（migrate + report）

## 目标与边界

用户要为 `ledger.py` 提供两个真实 CLI：`migrate` 把 `legacy/` 这样的 CSV 目录递归合并成一个 JSON 数组；`report` 从该 JSON 汇总计数与总额，支持 `--customer` 精确匹配和 `--min-cents` 最低金额筛选。

`migrate` 已在上一轮完成并通过。本轮补齐 `report`，同时保持已有迁移契约、错误处理和原始数据只读要求不变。原始数据在 `legacy/`，只读。

## 已定方案与约束

- 金额用字符串正则校验后按整数分计算，绝不经过 `float`。接受 `0`、`12`、`0.10`、`12.34` 这类写法，小数最多两位。
- 明确拒绝：负数、`NaN`、`Infinity`、指数格式、多于两位小数、空金额。
- 表头必须恰好是 `id,customer,amount`；`id` 与 `customer` 非空；`id` 跨文件唯一。
- 先完成全部解析和校验，再原子写入（临时文件 + `os.replace`），所以任何错误都不会触碰已有输出文件。
- JSON 数组按 `id` 字符串排序，每行只有 `id`、`customer`、`amount_cents`。
- 递归枚举 `source-dir` 下所有 `.csv`（后缀大小写不敏感），按路径排序读取，保证重跑确定。
- `report` 的输出是只含 `count`、`total_cents` 两个整数的 JSON 对象，打印到 stdout。`--customer` 按完整名称精确匹配，无匹配时两项为 0。
- `--min-cents` 默认 0，只统计 `amount_cents` 大于等于阈值的记录，可与 `--customer` 任意组合。负数、非整数和缺少参数值都以非零码退出，stdout 不输出结果。
- `report` 只读取 ledger JSON。文件缺失、JSON 损坏、行字段类型不对或金额为负时，以非零码退出并写 stderr，不修改 ledger。
- 回归检查用标准库 `unittest`，从真实 CLI 入口驱动。

## 证据与决定

- `legacy/` 实际内容：`01.csv`（Alice/Bob）、`02.csv`（张三/Bob）、`nested/03.csv`（Alice/张三），共 7 行，覆盖中文客户名、整数金额、两位小数、嵌套目录。
- 可重跑检查：`python3 tests/test_migrate.py`（8 个 migrate 测试）和 `python3 tests/test_report.py`（10 个 report 测试），也支持 `python3 -m unittest discover -s tests`。本轮实测 discover 共 18 个测试，约 1.8 秒，全部通过。
- report 的期望值由 `legacy/` 原始行手算：10、20、105、1234、200、100001、0，总和 101570 分。
- 新增检查确实能挡住错误（在 `/tmp` 的完整副本上改坏 `ledger.py` 后运行 discover）：
  - 把阈值判断从 `>=` 改成 `>` 时有 6 个测试失败；
  - 忽略 `--customer` 条件时有 2 个测试失败；
  - 允许负数阈值时有 2 个测试失败。
- 检查确实能挡住错误（上一轮 migrate，在 `/tmp` 的副本上故意改坏后运行）：
  - 金额改成 `int(float(raw) * 100)` 时有 5 个子用例失败；
  - 改成 `round(float(raw) * 100)` 时大额用例失败；
  - 去掉按 id 排序时排序断言失败；
  - 在校验前先写输出时，全部“不写坏输出”用例失败。
- 当前实现接受的边界写法（用户未逐条点名，按“普通写法”理解）：前导零（如 `007`）接受；空行视为列数不符而拒绝；目录里没有 CSV 时输出 `[]`。
- `--min-cents` 用 Python `int()` 解析，因此 `+5`、`1_000`、`-0` 会被当作整数 5、1000、0 接受。用户明确要求拒绝的负数、小数、字母和缺值均已验证非零退出。
- report 选择输出到 stdout，因为已有接口写作 `report out.json [--customer NAME]`，没有输出文件参数。
