# 导出顺序

## 结论

导出记录保留上游返回的原始顺序。导出阶段不按名称或其他字段重新排序，也不为了看起来整齐做二次编排。

这么做是因为已经签署的合作协议用原始序号对账。导出文件一旦重排，序号和协议各行对不上，对账就要人工还原顺序。

适用边界是所有导出路径，包括将来新增的导出格式和按条件筛选后的导出结果。筛选可以去掉行，但不能改变留下的行的相对顺序。

## 依据

- 类型：用户决定，2026-11-14 接入 ByIssue 时确认。
- 证据或复核方式：取一份导出文件与合作协议的序号列逐行比对，行序应当一一对应。本记录写入时没有拿到协议文本，比对尚未执行。
- 观察条件、版本或环境：结论来自用户说明的业务背景，不是从代码或运行结果推断的。

## 重访条件

合作协议重新签署时重新讨论这条决定。其他情况一律保留原始顺序，包括有人认为按名称排序更方便阅读时。

如果上游接口不再提供稳定的原始顺序，先查清上游排序依据，再回来更新本记录，不要自行在导出阶段补一个排序。
