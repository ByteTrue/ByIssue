# 账单迁移工具

## 目标与边界

`ledger.py` 已完成两个阶段。

- `python3 ledger.py migrate <source-dir> <output.json>` 递归迁移目录下所有 CSV，生成按 id 排序的 JSON 数组。
- `python3 ledger.py report <output.json> [--customer <name>] [--min-cents <n>]` 读取迁移结果，向 stdout 输出一个 JSON 对象，键为 `count` 和 `total_cents`。

原始数据位于 `legacy/`，保持只读。不安装依赖，不提交或推送。

## 已定方案与约束

- CSV 表头必须恰好是 `id,customer,amount`，顺序和拼写都不能变。
- `id` 与 `customer` 非空。重复 id 按错误处理，包括跨文件重复。
- `amount` 只接受非负十进制写法，最多两位小数。接受 `0`、`12`、`0.10`、`12.34`；拒绝负数、`NaN`、`Infinity`、指数写法、超过两位小数和空值。
- 金额按字符串拆分整数与小数部分换算成整数分，全程不用 `float`。
- 任何 migrate 错误都以非零码退出，错误写 stderr，`output.json` 保持原有字节不变。
- 迁移先完成全部读取、校验和排序，再原子替换输出文件；任何输入错误都发生在写文件之前。
- CSV 发现使用递归匹配 `*.csv`，并按路径排序保证稳定。JSON 使用固定键顺序 `id`、`customer`、`amount_cents`，重跑结果逐字节一致。
- report 未指定 customer 时统计全部；指定时按完整名称精确匹配，区分大小写。没有匹配时 `count` 与 `total_cents` 均为整数 0。
- `--min-cents` 默认 0，只统计 `amount_cents >= 阈值` 的记录，可与 `--customer` 同时使用。
- `--min-cents` 只接受由数字组成的非负整数。负数、小数、指数、正号、空白和空串都写 stderr 并以退出码 2 结束。
- report 不写任何文件。输入 JSON 缺失、不是数组、记录缺字段或金额不是非负整数时，写 stderr 并以退出码 1 结束。

## 证据与决定

- 接入 ByIssue 时运行 `python3 .agents/skills/bi/scripts/init_byissue.py --project .`，新建 `byissue/work/` 与 `byissue/memory/`。
- `legacy/` 实际包含 `01.csv`、`02.csv`、`nested/03.csv`，覆盖表见 `scope.md`。
- 回归检查使用标准库 `unittest`，通过 subprocess 调用真实 CLI，不绕过入口。运行命令：`python3 -m unittest discover -s tests -v`；本轮 13 个测试全部通过。
- 本轮真实 CLI 证据：`python3 ledger.py migrate legacy <tmp>/out.json` 后，默认 report 输出 `{"count": 7, "total_cents": 101570}`；`--customer Alice` 输出 `{"count": 3, "total_cents": 135}`；`--min-cents 200` 输出 `{"count": 3, "total_cents": 101435}`；`--customer Bob --min-cents 200` 输出 `{"count": 2, "total_cents": 1434}`；`--customer 张三 --min-cents 100001` 输出 `{"count": 1, "total_cents": 100001}`。
- 非 UTF-8 输入和目录路径都让 report 以 exit=1 退出并写 stderr，没有生成 traceback。
- 迁移前后三个 `legacy/*.csv` 的 SHA-256 完全相同，report 前后迁移 JSON 的 SHA-256 也相同。
- 故意做坏的副本把 `--min-cents` 直接交给 `int()`，并把过滤条件从 `>=` 改成 `>`。同一套测试出现 7 个失败，覆盖负数、正号、空白、默认阈值和边界值，说明这些检查确实挡住了对应错误。
- report 的 stdout 形状选为单行 JSON 对象，便于脚本继续处理；键顺序固定为 `count`、`total_cents`。
