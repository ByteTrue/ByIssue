# 一次授权动作不该翻转整场会话的姿态

## 预期与实际

**预期：** 用户说「先继续 talk」，会话就应该留在讨论姿态——不落盘、不建事项、不提施工方案，直到用户确认出口。`talk.md` 和 `SKILL.md` 授权边界都写了这件事。

**实际：** 用户在讨论中批准了一个需要动手的动作（自举），agent 执行完之后**整场会话的姿态悄悄翻成了执行**：接下来每一轮都以「要我现在就……吗」结尾，把讨论转成施工提案。用户连续两次手动拉回。

**最小场景：** 长 Talk 中出现任意一次被授权的落盘动作。

## 根因

不是「急」。是**姿态到底是会话级还是动作级，从来没有定义过**。一次被授权的动作没有边界，于是整个会话跟着翻。

两处在帮倒忙：

- `SKILL.md` 授权边界第一条「方向已经确认且用户要求执行时，持续推进到完成，不要在正常步骤之间反复确认」——又强又通用，在 Talk 里有害，因为 Talk 的价值恰恰是不要过早收敛。
- `talk.md` 的收住条件是单向的：只管「什么时候该收」，收了就给出口草案，长探索里这个引力一直在往执行拽。

而且这属于同一类失败的第三例（另两例：沉淀不触发、讨论中拍板不立碑）——规则写了但是描述句，不触发。

## 方案方向

- 明确姿态的作用域：授权动作是**动作级**的，执行完回到原姿态；切换姿态需要显式信号。
- 给 Talk 一个「留在这里」的反向条件，而不只有收住条件。
- 参考 `grill-with-docs` 的 `disable-model-invocation: true`：某些模式干脆不让模型自行进入，是一种更硬的稳定办法。
- 与 `001` 同源：把「执行完回到原姿态」写成祈使句，不要写成描述性边界。

## 验证

路由测试（见 `byissue/issues/004-o-posture-routing-regression-tests.md`）加一条多轮 case：Talk 中插入一次授权动作，断言下一轮仍在 Talk——不产出施工提案、不落盘。
