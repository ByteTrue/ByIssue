# 收尾与提交契约缺正面时序导致重复提交与重复跑 CI

## 预期与实际

**预期：** 受管理事项实现完成并收尾时，业务代码、事项改名（`-o-` → `-x-`）与毕业回写合并为单次提交，只触发一次 CI。

**实际：** 在真实项目（如 byspace 047 号事项）中，Agent 推进到实现完成并验证通过后，先分批提交并推送到远端主干，挂后台等 CI 跑通并汇报结果，最后才在全案总结末尾询问「是否需要授权关闭该 Issue」。用户授权后，Agent 只能将改名与回写作为第二笔提交推送到远端，导致重复产生提交并多跑一整轮 CI。

## 根因

1. **时序漏洞**：`close.md` 仅规定「相关变更同一 commit」，但没有规定关闭改名与业务代码的依赖顺序。
2. **软弱提示**：`do.md` 写道「用户授权 commit/push 时若 issue 仍未关闭，顺带再提醒一次」，显式默认了「代码可以在事项关闭前先行提交推送」。
3. **缺少正面主干**：收尾流程没有串联成清晰的正向时序流水线（实现验证完成 → 收尾汇报与关闭建议 → 授权后关闭回写与代码合并提交）。

## 修复方案

遵守 1.6.0「否定式表述要挣得它的注意力成本」原则，不堆砌「切忌/禁止先提交后问关闭」等消极大象词汇，而是确立唯一的正向操作时序：

1. **`do.md`**：收尾汇报附带关闭建议与沉淀候选；用户授权提交时，将关闭改名、毕业回写与业务代码合并为单次 commit；用户明确要求暂不关闭时才单独提交代码。
2. **`close.md`**：明确关闭改名与毕业回写作为代码变更的一部分在同一次提交中完成；顺带清理 1.5.0 残留的三处「Agent 指令」字样。
3. **`fast.md` 与 `SKILL.md`**：对齐正向时序表述。


## 关闭结论

1. **正向主干成型**：
   - `do.md` 将原本软弱的「顺带再提醒一次」收窄为「收尾汇报给出关闭建议与沉淀候选；用户授权提交时，将关闭改名、毕业回写与业务代码合并为单次 commit」。
   - `close.md` 明确关闭改名与毕业回写作为代码变更的一部分在同一次提交中完成，代码先行提交时才单独成笔。
   - `fast.md` 与 `SKILL.md` 表格同步对齐为正向时序。
2. **守住禁止大象原则**：没有使用「禁止先提交再问关闭」等消极大象词汇，直接用唯一操作流水线消除时序漏洞。
3. **遗留清理**：一并清除了 `close.md` 中 3 处残留的「Agent 指令」字样。
4. **验证**：全仓 `tools/check-skill-repository.py` 校验通过；改名前 grep 0 处悬挂引用。
