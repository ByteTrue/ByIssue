# 定义什么不该进 Project Spec，并把毕业改成筛选

## 做成以后是什么样

`spec.md`、`close.md` 和 Project Spec 模板给出一条可执行的判据：**进 spec 的只有代码里重建不出来的东西**（统一语言、边界与被排除方案、长期质量约束、做/不做）；能力如何运作、架构地图、数据流叙述不进。Epic 关闭时的毕业动作从「合并稳定结论的具体内容」改成「筛出代码里没有的那部分」。

**范围：** 包含 `spec.md` 行动指南与产物契约、`close.md` 毕业规则、`templates/entities/project-spec-index.md`、`docs.md` 里相关表述的归属对齐。不包含存量 spec 的批量重写（见下），不包含 Epic Spec（它描述还不存在的东西，不腐，不动）。

## 为什么现在做

决策与完整论证见 `byissue/decisions/004-project-spec-drops-implementation-description.md`。要点：Project Spec 结构性必腐——它描述已经存在的东西，天生是代码的第二份表述。而现行 `close.md` 明写「不能只写『见某 Epic』，要合并具体内容」，等于在催 agent 写最容易腐烂的那类文字。

现状证据：三个真实仓库的 spec 共约 1400 行，其中 AGCopilot 的 311 行里「能力地图」「架构地图」正是腐化第一现场，而同一文件里的「统一语言」「状态与数据边界」不会腐——差别就在可重建性。

`docs.md` 其实早有一句「代码路径只作为证据索引或落点」，原则是对的，是 `spec.md` 的落地契约背叛了原则。

## 方案方向

- 判据写成一句可执行的：**代码里重建不出来的，或能被机器校验的，才进 spec。**
- 存量不批量重写（那是另一次 audit）。改成下次 close 回写到某一节时，顺手按新尺子处理那一节——与 `001` 共用「收割而不另起一件事」这条原则。
- 注意副作用：这条落地后，spec 分层压力会自然消失（AGCopilot 那 311 行按尺子过一遍大概掉到一百来行），**不要再单独做一个分层触发器机制**。

## 验证

拿 AGCopilot 现有 `spec/index.md` 做一次干跑：按新判据逐节标记「留 / 删 / 降为落点」，确认删掉的确实都是 `ls` 加读文件头能重建的，留下的确实都重建不出来。

## 关闭时

- 回写候选：判据本身属于长期约束，应进 ByIssue 自己的 `byissue/spec/index.md`。
- 相关：`byissue/talks/001-...` 第 4–5 节；`byissue/decisions/004-...`。

## 执行记录

- `spec.md` 三处原则改写：新增「只写代码里重建不出来的东西」作为准入判据并点明 Project Spec 结构性必腐 / Epic Spec 不腐；删掉「主叙事围绕项目怎么用」和「先让人认识能力，再让人修改能力」那套三层读者模型（正是它要求写「怎样运作」）；行动指南里四个读者问题换成一句准入追问，分层退化为「内容多到读不下去再拆」。
- `close.md` 毕业规则从「搬运具体内容」改成「筛选」：回写前先过准入判据，多数 Epic 关闭时真正该进 spec 的只有几个词、一两条边界和被排除方案。关闭 epic 的检查清单和产物契约同步改写。
- `templates/entities/project-spec-index.md` 自检项换成：项目是什么 / 统一语言 / 做与不做 / 为何这样选、排除了什么 / 长期质量约束 / 稳定界面约束 / 阅读路径，并把准入判据写在模板顶部。
- `docs.md` 对齐：「使用叙事」改为「准入先于组织」并把判据归属指回 `spec.md`；删掉「project spec 优先按使用场景、能力建立地图」和对应的一条反例。
- 顺带：`spec.md` 的「核心理解不引用代码」不再说「按能力组织」。

## 验证

**真跑（本仓库）：** 按新判据重写 `byissue/spec/index.md`。删掉「现在有什么」整节（各文件做什么，`ls` 加读文件头可重建），补上原本缺失的「统一语言」（姿态 / 姿态文件与原则文件的二分 / 源头与部署副本 / 描述句与祈使句）——**这些在文件系统里看不出来**。52 → 47 行，行数几乎没变但内容换了一遍，正是判据想要的效果。

**干跑（AGCopilot 311 行）：** 按判据逐节分类——

| 删（可从代码重建） | 行数 |
|---|---|
| 能力地图 | 70 |
| 使用路径 | 101 |
| 架构地图 | 39 |
| **小计** | **210** |

留下的是：这个项目是什么 6、当前方向 11、状态与数据边界 9、统一语言 12、当前边界 18、关键考量 15、阅读路径 10、证据索引 18，约 **99 行**。**311 → 约 100 行，砍掉 68%**，且分层压力自然消失——印证了「不要再单独做一个分层触发器」。未改动该仓库文件，只做测量。

`python3 tools/check-skill-repository.py` 通过。

## 关闭结论

准入判据（只写代码里重建不出来的东西）落在 `spec.md`，`close.md` 的毕业改为筛选，模板与 `docs.md` 对齐。判据在两个真实对象上验证过：本仓库 spec 重写一遍、AGCopilot 干跑砍掉 68%。

**毕业回写：** 判据本身归 `skills/bi/references/spec.md`（技能契约），论证归 `byissue/decisions/004-project-spec-drops-implementation-description.md`。存量 spec 不批量重写，随下次 close 逐节收敛——这条已写进 decision。

**遗留：** 分层触发器**不做**（判据落地后分层压力自然消失），已在本 issue 方案里记明。
