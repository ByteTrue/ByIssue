## 候选汇总

三条候选，A、C 来自 M4 的测试写法，B 由 `readme-facts` + `generate.test.mjs:232` + `pi-equivalence` 三处同一类合成。

### A. 散文里的命令由测试按原样执行（`close.md` 的改名修引用 recipe）

- **做什么：** 把 `skills/bi/references/close.md:19`「**任何改名都先修引用。**…改名前用**确切的旧全名**（去掉结尾的 `.md`）做一次固定串搜索：`grep -rnF --exclude-dir=.git "<旧全名>" .`」这一整段（含「两端不是名称字符才是本事项」「后面直接续着更多名字是同日邻居」「跨树同名跳过」「依赖目录跳过」四条判法）做成夹具测试：造一份临时 git 仓库，放同日同前缀邻居、中文名事项、跨 trees 同名事项、`node_modules/` 噪声，执行 `close.md:19`/`:78`/`:115` 里那条命令，逐条按那四条判法分类，断言「本事项引用集合」恰好正确、改名后复跑为 0。pstack 的做法是 `tests/shipping-git.test.mjs:8-11` 从 `merge-safety.md` 的 ` ```sh ` 块正则抽 recipe、`if (!recipe) throw new Error('merge-safety.md has no restack recipe')` 保证「散文里的命令还在」，`:17` 用 `sh -e -c` 真跑。
- **挡什么：** 本仓最贵的一次复发。`CHANGELOG.md:120`：`close.md` 原命令是 `grep` `{日期}-o-`，会把**邻居**的引用改成不存在的路径（已复现）；随后四个正则「all looked correct on paper, three came from a review, and only a Chinese fixture killed the last one」——`[^A-Za-z0-9_-]` 边界在中文名下失效，把 `…-o-训练计划` 也匹配到 `…-o-训练计划日历.md`。三次写出不存在路径，靠的都是人工搭夹具。同类缺口今天仍然敞着：散文改了命令，没有任何检查会因为命令本身错而红（checker 只查路径存在性）。
- **零依赖做法：** 标准库 Python：正则从 `close.md` 抽出 `grep -rnF` 那几行（抽不到就失败，与 pstack 的 `throw` 同义），`tempfile.TemporaryDirectory()` 造三个夹具（同日邻居 / 中文名 / 跨树同名），`subprocess.run(["bash","-lc",cmd])`，比对命中行集合。
- **落点：** `tools/close-reference-repair-selftest.py`（与 checker 分开：它测的是散文里那条 `grep` 命令与判法，不查仓库结构，所以不该挂进 checker 的五项里），并在 `byissue/spec/index.md:38-52` 那张表新增一行「改名修引用的 `grep` 判法」，强制者写这个脚本。
- **成本：** 一个约 80–120 行的脚本，夹具三份；跑起来是毫秒级。风险：`close.md` 里那段命令的措辞一变，抽取正则要跟着改——所以抽取失败必须报错（pstack 的 `throw` 就是干这个的），否则会退化成静默通过。

### B. 能从树推导的事实（文件数、版本、被点名的工具）钉到树

- **做什么：** 三处合成一条检查：① `byissue/spec/index.md` 里「`references/` 下的 N 篇」「N 个 `.md`」这类数字与 `skills/bi/references/` 的实际文件数一致；② `CHANGELOG.md` 首个 `## ` 标题等于 `VERSION`（现在是只查反方向）；③ 散文里点名的 `tools/…`、`byissue/…` 文件真实存在（`byissue/` 那一半已有，`tools/` 那一半没有）。pstack 对应：`tests/readme-facts.test.mjs:1-2`「Each is derivable from the tree, so this pins every occurrence to its source instead of trusting a hand edit to keep up」；`tests/generate.test.mjs:232`「a heading newer than VERSION fails naming both, so an entry without a bump cannot ship」；`tests/pi-equivalence.test.mjs:54`「every extension or script row names a test that exists」= 文档声称的覆盖必须指到一个真实存在的断言。
- **挡什么：** 已经发生的漂移：`byissue/spec/index.md:17` 写「20 篇」，实际 22 篇（`writing.md`、`large.md` 先后加进 `references/`，`CHANGELOG.md:62`、`:53`），而这句话每次改仓库都会被读到，`byissue/issues/2026-10-29-x-ponytail-audit.md:13` 里抄的「20 篇」也跟着过期。同一句还承担「姿态文件 / 原则文件的分类在文件系统里看不出来」这个判断，数字错会让读者以为有漏文件。版本方向：先写 `CHANGELOG` 小节、忘了 bump `VERSION`，今天 checklist 不报（`tools/check-skill-repository.py:45-46` 只查 `VERSION` 有小节）。工具名方向：`byissue/spec/index.md:41-49` 那张表点名的守卫一旦改名，表就成了假陈述，而 `byissue/decisions/009-quantified-claims-carry-their-evidence.md:14`「附出处不能保证结论正确，但能让它可被推翻」正是这条要守的东西。
- **零依赖做法：** 在 `tools/check-skill-repository.py` 里加一节 `check_derived_facts`：`len(list((SKILL/"references").glob("*.md")))` 对 `byissue/spec/index.md` 里的 `(\d+) 篇` / `(\d+) 个 ` 比对；`CHANGELOG.md` 第一个 `^## (\S+)` 与 `VERSION` 相等；复用现有 `pattern` 把 `byissue/**` 与 `spec/index.md` 里的 `tools/[\w.-]+` 逐个 `ROOT / name` 存在性判断。
- **落点：** `tools/check-skill-repository.py` 新增一节 + `tools/check-skill-repository-selftest.py` 三个夹具（数字改错、CHANGELOG 领先 VERSION、`tools/` 名写错）。
- **成本：** 检查约 25 行、夹具 3 个各 3 行。①的一个坑：`byissue/` 旧记录里合法地写着过期的数字（那是历史记录），所以只查 `spec/index.md` 这类**当前契约**文件，不要全仓扫；这一点必须写在检查的 docstring 里。

### C. 散文里裸写的文件名必须是对得上的一个包内文件（低优先）

- **做什么：** 把 `skills/bi/**/*.md` 里形如 `` `quality.md` ``、`` `ff-issue.md` ``（小写、无路径分隔符、`.md` 结尾）的名字收集起来，断言能在包里按 **basename** 找到同名文件（注意 `issue.md`、`ff-issue.md` 在 `templates/entities/` 下，只查 `references/` 会误报），白名单只放 bi 自己的用户项目产物名。pstack 对应：`tests/skill-references.test.mjs:1-4`「Nothing resolved them until now, so a renamed directory left dangling references no tool could see」。
- **挡什么：** 改名后散文里的提及无声存活。历史实例是 `byissue/spec/index.md:27`「`done/` 在 1.1.0 删除后仍在三处存活」与 `CHANGELOG.md:121`「`upstream` left dangling in `domain-modeling.md` after the header came out」。**诚实地说**：`done/` 是目录名不是 `.md`，这条检查抓不到那个已发生的实例；它防的是下一次改名 `quality.md`/`ui-spec.md`/`economy.md` 这类（散文里分别有 3/2/1 处裸写，`grep -rhoE '`[a-z][a-z0-9-]*\.md`' skills/bi` 共 47 处）。
- **零依赖做法：** 在 `check_skill_links` 里加 `BARE_RE = re.compile(r"`([a-z][a-z0-9-]+\.md)`")`，命中名字若不在 `{p.name for p in SKILL.rglob("*.md")}` 里且不在 `{index.md, ledger.md, terms.md, plan.md, changes.md}`（bi 定义给用户项目的产物名，出处 `skills/bi/references/spec.md:23`、`:74`）就报。
- **落点：** `tools/check-skill-repository.py` 的 `check_skill_links` + selftest 一个夹具（把某处 `quality.md` 改成 `quality2.md` 必须报）。
- **成本：** 检查约 15 行、夹具 3 行。已实测今天跑一遍零命中（47 处裸名里 6 个能在包内按 basename 找到，其余 5 个全在白名单里），所以它是零噪音的防回归，而不是修现状——这也是它排在 A、B 之后的原因。
