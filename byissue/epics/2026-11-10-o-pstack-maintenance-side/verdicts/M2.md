## 候选汇总

四组候选，覆盖表里 5 个 `[候选]` 行（C3 合并两行）。顺序按「挡住的失败有多疼」排。每条都写明零依赖做法与成本；三条不需要新代码，一条是 stdlib Python。

### C1 仓库级相对链接与反引号路径可达性检查（并 `.markdownlint-cli2.jsonc` 里那一半）

- **做什么。** 现在的 checker 只解析两处路径：`skills/bi/` 里的 Markdown 链接与 `references|templates|scripts|agents` 前缀的反引号路径（`tools/check-skill-repository.py:64-80`），以及全仓 `byissue/(issues|epics|notes|talks|decisions)/` 前缀的悬挂引用（`:172-215`）。补一遍**全仓 Markdown**：`[文字](相对路径)` 与反引号里的 `tools/...`、`byissue/...`、`技能包内路径`，两处都按所在文件的目录解析，解析不到就红；`#锚点` 只取 `#` 前那段（pstack 的做法：`CONTRIBUTING.md:110`「**A missing or escaping local Markdown link.** `tools/validate-skills.mjs` resolves bare, `./`, `../`, and reference-style targets against their Markdown file. Every local target must exist inside `plugins/pstack/skills`」、`:111`「The same tool resolves every backticked relative path against its Markdown file and against the plugin root… A token that lands on a real file or directory outside `plugins/pstack/skills` fails」；CI 侧对应 `.github/workflows/ci.yml:413-435` 的 lychee job 与 `:400-411` 的 markdownlint job，规则集见 `.markdownlint-cli2.jsonc:5-14`）。pstack 的 lychee 连 `#fragment` 也解析（`:116`「a fragment link to a heading that is not there」），ByIssue 的锚点目前一律忽略（`tools/check-skill-repository.py:23` 注释「anchors allowed, path captured」）。
- **挡什么。** ①「文档指向一个不存在的命令」——真发生过：`byissue/issues/009-x-ff-tidy-tools-scripts.md:14`「`byissue/spec/index.md` — 发布链路第二步还让人跑 `tools/check-posture-routing.py`，**那个脚本早已删除**。这是真·活缺陷：文档指向一个不存在的命令」。②「写的路径形态根本不可能存在」——`CHANGELOG.md:121` 记过「a cross-Epic reference shape missing its date+state prefix, i.e. a path that cannot exist」。③ 现在就有的两处解析不到的链接（本次实跑）：`byissue/issues/2026-10-22-x-ff-review-blind-spot-probes.md:25` 的 `[debug](debug.md)`、`byissue/issues/009-x-ff-tidy-tools-scripts.md:15` 的 `nonexistent.md#x`（后者是刻意写的负向夹具，前者不是）。这条正好补上现有 checker 的结构性盲区：`byissue/spec/` 与仓库根文档没人管。
- **零依赖做法。** 在 `tools/check-skill-repository.py` 加一个 `check_repo_links(report)`，复用已有 `LINK_RE`，再加一条反引号路径正则和一个「按文件目录解析」的循环；不引 markdownlint、不引 lychee。规则只取「能不能解析」，不取空格/alt/表格列数（`tools/check-skill-repository.py:9-11` 的 docstring 已给这条定调：「Contract wording is deliberately not checked — grepping for phrases here would only create a second, drifting copy of it」——所以新增的只能是「能不能解析」这类机械事实）。
- **落点。** `tools/check-skill-repository.py` + `tools/check-skill-repository-selftest.py`（各加一两条：链接指向不存在文件、反引号路径指向已删除脚本）。因为发布链路第 1 步就是跑 checker，落进去即自动生效。
- **成本。** 约 25–35 行 Python + 2 个 selftest 用例，一次改完；此后零维护（路径集合从文件系统推，不手抄清单）。**注意一个真实误报源：** `byissue/` 下的历史记录里刻意写坏的路径（如 `nonexistent.md#x`）会被新检查判红，落地时要么给历史记录一个显式豁免写法，要么承认它就红着——需要你定。

### C2 把「靠记性」的两步落成一条可跑的本地门禁（并 `.pre-commit-config.yaml` 与 CI 的 skills-only job）

- **做什么。** pstack 有两层同一件事：`.pre-commit-config.yaml:6-13` 一个 local hook，`entry: bun tools/generate.mjs --check`、`always_run: true`（注释 `:1-4` 交代 `prek install` 一次、读工作树不读 index）；CI 里 `skills-only` job 把 checkout 真的装一遍再 `diff -qr plugins/pstack/skills .agents/skills`（`.github/workflows/ci.yml:141-158`，注释 `:149-152`「the canary proves the tree in the PR instead of whatever is on main」）。ByIssue 对应的是发布链路头尾两步，两步都没有强制者。
- **挡什么。** ①「装机副本落后仓库一版」——真发生过两次：`byissue/issues/015-x-ff-grilling-verbatim-upstream.md:17`「顺手发现：装机副本整体落后仓库一版——`~/.pi/agent/skills/bi/` 的 SKILL.md 缺「直接要求提交/推送」行、do.md 缺收尾扩句（1.8.0 内容）」，`byissue/issues/016-x-ff-absorb-upstream-grill-family.md:15` 才「顺带补上 ff 015 遗留：装机副本此前整体落后 1.8.0 一版」。这正是 `byissue/spec/index.md:53`「rsync 同步部署副本 | **无**，忘了就等于没改」的代价：评测子 agent 加载的是副本，副本旧了整轮评测测的是旧版本（`tools/posture-scenarios.md:26`「改完必须先 rsync 同步到那份、用 `diff -rq` 确认一致再跑，否则测的是旧版本」）。②「改了没跑 checker 就提交」——发布链路第 1 步同样只靠记性。
- **零依赖做法。** 一个 `tools/release-gate.py`（或 `.sh`，两个动作都不需要 Python 特性）做两件事：跑 `check-skill-repository.py`；`rsync -a --delete skills/bi/ <部署副本>` 后 `diff -rq` 两侧、不一致就非零退出。部署副本路径的找法仓库里已经有现成的一句：`byissue/notes/2026-11-09-bi-behind-magpie-index-is-rarely-opened.md:21`「本机找法：`readlink -f ~/.pi/agent/skills/magpie-skills/.skills/bi`」。再加第二个可选件：`tools/githooks/pre-commit`（4 行，只跑 checker）+ 一行 `git config core.hooksPath tools/githooks`；不需要 pre-commit 框架、不需要 prek。
- **落点。** 新文件 `tools/release-gate.py`（或 `.sh`）；`byissue/spec/index.md:58-66` 发布链路的第 1 步与 rsync 步改成「跑这条命令」；`:51-54` 里「改完 `skills/bi/` 跑对抗审查」（`:51`）与「rsync 同步部署副本」（`:53`）两行的强制者从「无」改成这条脚本。
- **成本。** 30–50 行 shell 或 Python，外加 spec 两行改动。**两个要你定的点：** ① 部署副本路径写死还是从参数/env 取（写死会在换安装方式时静默失效）；② 门禁脚本要不要在缺部署副本时失败（判失败会让「没装 bi 的机器」无法发布，判通过则第一条失败面又回来了）——pstack 的选择是 CI 里拿一份新装的副本比对源（`ci.yml:141-158`），即不依赖本机副本状态。**拿不准：** 「提交了 checker 红的状态」没有一次可引的具体记录，这一半的收益是推理出来的，不是历史教训。

### C3 分发包里的上游归属，以及仓库根缺的那份 LICENSE（并 `NOTICE.md`、`LICENSE`）

- **做什么。** pstack 在最外两层各放一份归属：`LICENSE:1-5`（MIT 正文 + 上游/port 两行版权）与 `NOTICE.md:3`（「This repo is a port of upstream MIT-licensed work … All upstream copyright notices and license terms are preserved.」）+ `:7-27` 按上游 commit 分行的文件清单。ByIssue 有一份**逐字节镜像**分发出去（`skills/bi/references/grilling.md`，`byissue/spec/index.md:18`「**正文为上游 `mattpocock/skills` `grilling` 的逐字节镜像（ff 015）：勿手改，同步上游时整文件替换。**」，`domain-modeling.md` 读侧为句级镜像 `:19`），而这份归属只写在维护者文档里（`byissue/spec/index.md:18-19`、`byissue/issues/015-x-ff-grilling-verbatim-upstream.md:13`），`skills/bi/` 里一句都没有；仓库根也没有 `LICENSE` 文件，但 `README.md:218`「MIT License · 基于 @liuzhengdong 的 CodeStable」与 `:14` 的 MIT badge 已经对外声称 MIT。
- **挡什么。** 「MIT 副本发出去却没带版权与许可声明」——这一类事后补不回来（已安装到用户项目的副本收不回）。它同时是**单一归属**问题：为什么这份文件是逐字节镜像、同步时谁替换谁，只写在 byissue 的维护者文档里，读到文件本体的用户看不到。
- **零依赖做法。** 两个纯文本文件，零代码。许可正文取标准 MIT 全文，版权行并列上游与 port；归属表只列真正被镜像/改编的上游（`mattpocock/skills`），不抄 pstack 那种按 commit 分 20 行的表（ByIssue 只有一个上游来源）。
- **落点，以及一个必须先解决的冲突。** 声明要**随包走**才有法律意义，而 `CHANGELOG.md:121` 记过一次反向清理：「`domain-modeling.md`'s upstream-provance header, which was maintainer autobiography in a distributed file」——ByIssue 刻意把上游出处从分发文件里拿掉了。所以落点只有两个选择，需要你定：**(a)** 放 `skills/bi/NOTICE.md`，这就必须在 `SKILL.md` 里被引用一次，否则 checker 会报 `packaged but nothing references it`（`tools/check-skill-repository.py:83-88`），成本 = 1 文件 + `SKILL.md` 一行 + 可能要在 `ENTRY_FILES`（`:32`）里加一项；**(b)** 只放仓库根 `LICENSE`，明说「分发包内的归属见仓库 NOTICE」，代价是那句声明不随包走。**拿不准：** 上游 `mattpocock/skills` 的具体许可证与版权行我这次没去核（只读到 ByIssue 说它是上游镜像），落地前要读一次上游 LICENSE。
- **成本。** 1–2 个文件，无代码；选择 (a) 时附带 1 行 `SKILL.md` 与 1 行 checker 白名单。

### C4 `.gitattributes`：`* text=auto eol=lf`

- **做什么。** `.gitattributes:1-2`「# Keep generator anchors and executable scripts identical on every platform.」/「* text=auto eol=lf」。
- **挡什么。** ByIssue 有两条字节级契约：`byissue/spec/index.md:18`「逐字节镜像」与 `:19`「句级镜像」。在 `core.autocrlf=false` 的 Windows 环境提交一次，CRLF 就落进仓库，镜像静默破掉——checker 全文按行正则、没有一个字节锚点，不会红。
- **零依赖做法。** 两行文本文件。
- **落点。** 仓库根 `.gitattributes`。
