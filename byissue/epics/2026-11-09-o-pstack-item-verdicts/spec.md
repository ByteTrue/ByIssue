# pstack 逐项裁定：每个技能、playbook、agent、hook 都有一个结论

> **读者：** 接着做这次逐项裁定的 agent，以及以后想知道「pstack 的某一项为什么没进 bi」的人。

## 要改变什么

第一轮吸收（`byissue/talks/2026-11-09-what-to-absorb-from-pstack.md`）是按类别裁定的。2026-11-09 用 pstack 目录机械列出 116 项，对照记录发现 77 项没有被点名，其中 22 条 principle 只有「内容和 economy 等大面积重叠」这一句类别结论，约 20 个技能和 playbook 没有任何结论，有几个（`visual-parity`、`perf-issue`、`benchmark-checklist`、`runtime-forensics`、`trace-forensics`、`create-verification-skill`）看起来和 bi 的缺口直接相关。这个 Epic 让每一项都有一条带证据的结论。

## 已定方案与必须守住

- **不 fork pstack，不做 v2，按条吸收。** 用户 2026-11-09 原话：「pstack 并没有实现我想要的效果，所以我这边的结论是否定做 v2 版本。继续只吸收优化我们的」。适用范围：长期。
- **逐项过一遍，要吸收的列给用户定，再一项一项落地。** 用户 2026-11-09 在选项「开新议题，按台账逐项过一遍」上确认；选项原文：「113 项写进台账，每项给『已有 / 吸收 / 不吸收+理由』；读文件交给 DeepSeek 子代理分组做，我核对；要吸收的列给你定，再一项一项落地」。选项里的 113 把 `agents/` 目录算成一项，展开成 4 个 agent 定义后是 116 项。
- **bi 的形态约束**，出处 `byissue/spec/index.md`「改这个仓库要守什么」：纯 Skill、单入口、零依赖（标准库 Python 加 Markdown）、主要用中文、不写 `AGENTS.md`、不假设可选外部扩展（如 ponytail）已安装。吸收候选违反其中任何一条的，结论是不吸收并写明哪一条。
- **读文件和初判交给低价模型的子代理。** 出处 `byissue/spec/index.md`「这个项目是什么」里用户 2026-11-09 的裁定。
- **一次一个议题。** 本 Epic 期间不开别的议题；落地阶段每个吸收项按发布链路单独改、单独验。

## 结论的判据

- **已有**：必须引出 bi 里的 `文件:行` 和原句，并说明那句在**同一个时点**让 agent 做**同一个动作**。「大面积重叠」「理念相近」不算已有，这正是本 Epic 要补的缺口。
- **候选**：说明它让 agent 在哪个时点做出什么不同的动作（`tools/prompt-review.md` 第 8 类），它纠正的是不是模型的真实默认，以及会落到 bi 的哪个文件。
- **不吸收**：理由必须是上面的形态约束之一，或者与 bi 现有契约的具体冲突（引 `文件:行`），或者它只服务 pstack 自己的机制（多模型、PR 流水线、宿主适配、hook）。
- 第一轮已经有结论的项，引用那条结论即可，但要核对那条结论是逐项的还是类别的；类别结论按本判据重新判。

## 当前方案

台账 [ledger.md](ledger.md) 按类型切成五个单元，可能产出候选的先做：U1 playbook，U2 principle，U3 与 U4 其余技能，U5 agent 定义与 hook。每个单元交给一个 DeepSeek 子代理读 pstack 原文和 bi 的对应文件，逐行给出结论与证据；父会话逐行核对引用是否真实、是否同一时点同一动作，核对不过的退回重判。五个单元做完后，把全部「候选」攒成一次问题交给用户裁决。
