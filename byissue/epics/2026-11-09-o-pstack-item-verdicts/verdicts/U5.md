## 候选汇总

### A. 保留一条注释的理由必须先被证明，证不成就删（来自 agent `comment-sicko`，判为 [已有·部分] 缺的那块）

**pstack 原句：** 「`IMPORTANT`, `do not remove`, `too risky`, `fine for now`, and long justifications are scent, not conviction. Before judging, I read nearby code. If its claim is not obvious there, I run `/how`, `/why`, or both」「Only a foreign keep-list gotcha proven true today on a live path crawls away.」「`/how` and `/why` read our code, so they cannot prove a rule that a dependency, platform, vendor, or protocol sets. When a comment states such a rule, I hunt in the documentation or source code of whatever sets it.」「When I cannot reach either, or what I read leaves the rule unsettled, the comment stays put as a `HOLD`, the one case where doubt is not meat.」「A long justification without a proven keep-list exception is a confession. Kill it.」

**bi 的缺口：** `references/economy.md:90` 的 keep-list 只要求「外部依赖、平台或协议强加、读代码看不出来的行为（写明出处）」，末句是「「不要删」「改之前先问 X」这类约束注释，能落成类型、测试或 lint 的先落成检查。」——注释自己声明「是 Safari 需要的」「删了线上会挂」时，bi 没有一步要求去依赖的文档或源码核实这个声明；落不成检查的那一类也没有归宿，按现有文字最省事的读法是留着。

**建议落点：** `references/economy.md`「交付前清理自己的 diff」，接在 `:90` 末句之后：keep-list 里的外部约束要指到当场能核实的出处（依赖文档、源码或平台说明），核不到或在读到的材料里不成立就按删除处理；只写了一长段理由而没给出处的不算保留理由。

**为什么是模型的真实默认：** 注释里的断言是模型最容易当成既有约束照办的一类材料——它读起来像需求、像别人的决定，而且这类注释恰好是唯一没法靠跑一次验证的，模型最省力的动作就是留着它、甚至在旁边再加一段解释。

### B. 用户已经贴了评审意见时，先独立审完再看（来自 agent `thermo-nuclear-review-subagent`，判为 [已有·部分] 缺的那块）

**pstack 原句：** 「Finish your **independent** audit first (fresh eyes). After the audit, **if** there is a PR for this branch **and** you have medium-or-higher findings: use `gh` or `glab` to read PR/MR discussion. Incorporate review-bot or human threads — validate, dedupe, and attribute sourced items in your report.」

**bi 的缺口：** `references/code-design.md:147` 的 Review 步骤 1 是「锁定范围；读相关代码与测试；扫本范围相关 `byissue/`。」，全目录没有一条讲用户给的现有评审意见、PR 讨论该在什么时候读。用户把「别人已经提了两条」贴进来时，模型没有约束说先自己过一遍。

**建议落点：** `references/code-design.md`「Review 动作」的「步骤」第 1 步之后加一句：用户已给出评审意见或 PR 讨论时，先把范围按自己的尺子审完再读，读到时逐条判成立、重复还是无据，成立的在汇报里标出处。

**为什么是模型的真实默认：** 已有的评审意见是现成的结论，模型会顺着它组织整份 review：只覆盖别人提过的点，或者直接同意，独立审计这一步被悄悄省掉。先读结论再找证据，和先审再对照，产出完全不同。

**不吸收的部分：** 该 agent 用 `gh` / `glab` 读 PR/MR 讨论、按 PR 是否存在决定流程，属于 PR 流水线，不进 bi。
