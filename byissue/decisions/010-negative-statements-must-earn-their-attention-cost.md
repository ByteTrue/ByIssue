# 否定式表述要挣得它的注意力成本

技能里的「不要 X」只有在 X 是模型的**强默认行为**时才保留。挡一个模型本来不会做的事有两重代价：占上下文，以及把那件事送进注意力——「不要想大象」。判据已写进 `byissue/spec/index.md`。

连带一条更具体的：**`SKILL.md` 永远在上下文里，所以它已有的规则不要在 reference 里重述。** reference 之间按需加载、彼此不能假定对方在场，`SKILL.md` 可以。这是单一归属原则用在否定式表述上的形式——之前它只被用在正面契约上。

## 这次清掉了什么

实测基线：345 处否定式表述 / 约 2200 行技能文本，约每 6–7 行一处（复现：`grep -c "不要\|不得\|禁止\|不应\|不能\|不自动\|不适用"`）。

- **「不自动 commit / push / 关闭」说了 7 次** → 1 次。原先 `SKILL.md` 一张表连续三行各说一遍，加上 `do.md` 两处、`close.md` 一处、授权边界一处。现在提到表外说一次，表格行只留各自不同的部分。这条挡的是真默认（模型极爱顺手提交），**规则留，重述删**。
- **「无边界全仓审计」在 5 个文件里各禁一次** → 0。`debug.md`、`complain.md`、`economy.md`、`explore.md`、`design.md` 的「不适用」小节各有一条。而主动全仓审计不是模型的默认，模型的默认恰恰相反。保留两处：`code-design.md` 的 Review 定范围规则（评测场景 ⑥「review 一下整个仓库」证明用户真会这么说）和同文件里「没有 audit 姿态」的立场声明——那是 Review 的归属文件。
- 「信息安全性与安全性不混称」3 处 → 1 处（归 `quality.md`，它定义九特征）。
- 「不要痕迹」在 `SKILL.md` 的 6 处重述收归「无痕迹例外」一节。

## 没做的

`docs.md` 的「反例」13 行纯负面小节保留。它虽然是正面原则的镜像，但给的是**具体形状**（「`index.md` 只有一张 topic 表」），比抽象原则好认；删了可能真丢判断力。这是本次唯一一处「纯负面但值得留」的判定。

## 背景

来自用户：「不要往提示词里去加那种莫名其妙的内容……不要去塞没有的提示词来影响模型的注意力。」同时确认技能里不存在「用户不说 bi 就别触发」这类元规则——那种偶尔触发、需要时主动说 `bi` 的状态是可接受的，不需要写进提示词。
