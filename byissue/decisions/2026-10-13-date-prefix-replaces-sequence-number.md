# 事项前缀从序号改为创建日期

每棵事项树的文件名以创建当日日期开头（`YYYY-MM-DD`），取代原来的「本树最大序号 + 1」。状态字母（`-o-`/`-x-`/`-d-`）、`ff` 标记、名称、物理归属全部不变，换掉的只是开头那一段。

理由不是「顺序号容易数错」，而是**顺序号必须从一个写作者看不见的状态里读出来**：真实仓库都在多个 git worktree 里并行工作，`ls byissue/issues` 结构性地看不到另一个分支上已提交的事项，所以「本树最大序号 + 1」是**按构造必撞**——不是执行不勤的偶发失误。实测 byspace 100 个 root issue 有 14 个撞号编号，pi-package-mono 123 个里 5 个。日期由时钟给出，不需要读任何文件，并行会话、worktree、克隆都不会撞。

选形态前核对过同类工作流：Trellis 写 `.trellis/tasks/MM-DD-name/`，Superpowers 写 `docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md`，OpenSpec 在活动期根本不带号，唯一还在编号的 Spec Kit 是**由脚本**取号而不是由模型取号。没有一个需要唯一性的方案是靠读目录得到的。

**没有解决的部分，要说准：** 日期同样不唯一——同一天建的多个事项共享同一个前缀。所以「引用必须给完整文件名」这条规则照旧成立，唯一性由它承担，而不是由前缀承担。`decisions/005` 的结论在这一层被继承而不是推翻。

**契约文本本身不写这段演变史。** `skills/bi/` 里只写现在成立的规则（日期不读已有文件，所以并行 worktree 不会撞号），理由、证据和被取代者留在这里。用户的原话是：用这个工作流的人没有任何必要了解工作流的演变历史。

取代 `byissue/decisions/005-accept-number-collisions-require-full-name-references.md`（该文件只在其末尾自行注明，不做整体改写）。

## 背景

来自用户原话：「当前还是比较常出现撞编号的事情」。第一轮归因（把它当成「创建时没重新查号」的执行问题）被用户当场否掉——他说大部分发生在不同 worktree 里，和创建时间没关系，那是结构性盲区。备选方案（日期 + 短随机后缀、日期 + 时分）未采纳：slug 已经足够区分，随机位交给模型生成不可靠，时分则让文件名更长而收益不明显。
