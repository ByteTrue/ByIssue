# 接受事项编号碰撞，改为强制全名引用

事项编号维持「本树最大序号 + 1」，不换方案。把「引用事项必须给完整文件名或目录名」从只约束 Epic Issue 扩展为通用强制规则。

实测过才这么定：AGCopilot 168 个事项里 14% 的编号被共用（`087` 撞了四次），但真正产生歧义的引用只有**个位数**——裸编号引用 61 处、完整文件名引用 48 处，抽查碰撞号 `018` 的 13 次引用里 11 次都写了完整目录名。**碰撞本身几乎不疼，疼的是「裸编号 + 碰撞」这个组合**，所以修引用比修编号便宜得多，也更对症。

真实备选是日期前缀 `20260921-x-name.md`，一度被采纳，随后被数据推翻：三个仓库里 81–88% 的事项会共享日期前缀（单日最多 13 个），比 14% 的编号碰撞差六倍，而且会把一个已知不可信的值（322 个事项里有 3 个不可能的日期）提升成身份。另一个备选（工具扫碰撞）只产出报告，不解决引用。

把话记死，省掉下次重量：**没有便宜的办法真正消除碰撞**——根因是两个并行会话同时读到同一个 max，要消除只能中心分配或随机后缀。既然伤害是个位数，正确答案是接受碰撞、让它不疼。
