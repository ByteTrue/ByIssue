# 一次性迁移不进工作流

规则变了以后，存量内容怎么办只有两个选项：**挑一次一次性手工处理掉，或者不动**。不允许第三种——把迁移义务写进技能、文档或任何日常步骤。

因为迁移是一次性的，而契约是永久的。「下次关闭时顺手按新尺子处理那一节」听起来很经济，实际是**给一次性的事收永久的税**：每次收尾都多一项检查，它只在头几个月有意义，之后永远是噪音，而且没人会去删。更糟的是它让漂移期无限长——存量一直带着已知会误导判断的内容，谁也说不清什么时候收敛完。

这条直接取代 `byissue/decisions/004-project-spec-drops-implementation-description.md` 末尾那句「随下次 close 回写时逐节收敛」。那句话是同一天写的，写的时候看着像「收割而不另起一件事」的漂亮复用，其实是两回事：收割的对象是**刚刚发生的工作**，迁移的对象是**过去的存量**。

判据变化不追溯这条已写入 `skills/bi/references/spec.md`，对所有使用者生效。

## 背景

来自用户的纠正：「这种迁移我们都不做，至少不要在技能或者文档、我们的工作流里去做，你要么就一次性手动改完，我们工作量不要塞迁移的动作进去，保持最简。」检查确认技能本体没有被污染——`onboard.md` 本来就写着「不迁移旧文档，不在 onboard 里强迁移」；唯一一处是 004 自己。
