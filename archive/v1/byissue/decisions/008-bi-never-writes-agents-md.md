# bi 的工作流不包含任何往 AGENTS.md 写东西的指示

`AGENTS.md` / `CLAUDE.md` 从 bi 的去处表里整个拿掉。记知识只有一个落点 `byissue/notes/`；毕业路由、maketools、onboard 里指向 Agent 指令的分支全部删除。遇到确实值得每次启动都知道的规则，照常写进 notes，然后**提示用户一句**——由用户自己决定、自己动手。

理由不是「写进去不好」，而是**用户不知情**。那类文件每次会话都注入，改一行等于改变该项目之后所有会话的判断面。这种影响不该作为「记一下这个坑」的副作用发生，用户往往在几周后才发现 agent 的行为变了却找不到原因。要加就该是用户自己开口。

取代 `byissue/decisions/007-bi-does-not-write-itself-into-agents-md.md`。007 只禁止技能为**自己的可触发性**写入，留着 `note.md` 那条正当路由；但那条边界在技能文本里并不严密——`note.md` 原文说 `AGENTS.md` 收「几乎每次启动都影响判断的规则」，「本项目使用 ByIssue」按字面完全符合。与其维护一条要靠读者自觉的窄边界，不如整条去掉。

代价照旧写明，但**要按实测说准**：不含流程词汇的说法（「加个字段就行，很简单」）技能**会打开，只是开得晚**——两轮评测分别落在第 6 和第 9 个调用，期间 agent 已经在自由探索，不保证动手前读到契约。用户想让它早点进来，就自己说一声 `bi`。

这是接受的边界，不是待修的 bug。迟到比不到轻得多，所以接受更站得住；但**不要把它记成「技能不会被打开」**——那比证据强，而且会让后来者以为存在一个更严重的问题。

## 背景

用户原话：「bi 工作流不要包含往 AGENTS.md 里写东西的指示，用户想要的话自己去和 llm 说，而不是被 bi 工作流在用户不知道的时候改了。」
