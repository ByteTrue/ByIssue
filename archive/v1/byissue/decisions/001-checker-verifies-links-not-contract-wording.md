# 发布校验检查链接可达性，不检查契约文字

`tools/check-skill-repository.py` 原本硬编码 34 个必需文件的清单，并 grep 一批中文短语（「最小充分变化」「什么时候必须画」等）来确认契约还在。改成：扫描技能内所有 markdown 的链接与反引号路径，双向校验——指向的路径必须存在，每个打包文件必须被引用到。

选它是因为 marker grep 只能证明字符串还在，证明不了契约成立，而且它本身就是契约的第二份副本：每次重写文案都要同步改校验，于是校验反而成了新的漂移源。文件清单同理——它是文件树的第三份副本，而且两个方向的失效都测不出来。可达性校验用 112 行换掉 254 行，并且抓到了四个从没被引用过的模板。

代价是接受了「契约文字无人守护」：语义漂移只能靠行为回归测试挡，那个东西现在还没有。

## 背景

改动发生在 1.2.0 的 ponytail audit 中。当时的直接证据是：`done/` 概念在 1.1.0 被删除后仍在三处存活，而旧 checker 的全部 marker 都是绿的——它检查的东西和会坏的东西不是同一批。
