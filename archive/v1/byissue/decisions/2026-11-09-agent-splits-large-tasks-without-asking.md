# 大任务由 agent 自己建 Epic、台账并拆单元，只在缩减范围时问用户

2026-11-09，用户在两个选项里选了「自己建 Epic、台账、拆单元并开工，只在要缩减范围时问」，没选「先给我看拆法和台账范围，我说开始再做」。适用范围：长期，所有用户交来的大任务。这之前 `do.md` 把「擅自建/拆事项」列为不适用，`spec.md` 要求 Epic 先经用户同意才能创建；对大任务，这两条现在不再适用。

以下是 agent 的判断。用户在 Codex 会话里说过：「我懒得手动拆」。1.12.0 又把用户的出场收成三处：开头给需求、中途做只有用户能做的决定、最后看总结。拆法和执行顺序不属于只有用户能做的决定；缩减范围（台账里标「不做」）属于，所以这一步仍然问。代价是拆法不合适时要到汇报里才看得出来，靠台账和三个重读时点兜底：漏项会在宣布完成前的对照里暴露。

讨论经过见 `byissue/talks/2026-11-09-large-tasks-ledger-and-reread.md`。
