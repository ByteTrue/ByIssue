# Review 补三类盲区探针，并把 bi 自己的失败模式做成一次性 retro

来源是与 billion-context 工作流的对照。它把「AI 最容易漏什么」从 1543 条 issue/PR 的实测数据里反推成清单；我们只取其中 bi 现有尺子缺的三格，其余（放行判据、版本优先、回归钉、双向断言、规则挂锚）经用户裁决不采纳。

- 改动：`skills/bi/references/code-design.md` — Review 段在「按严重度说话」之前新增「盲区探针」，三条：交叉与交互（同一状态两条路径写、跨模块时序、重入、旧快照无条件写回、先查后改的窗口）、静默丢失与覆盖（吞异常、丢字段、默认值替掉失败、覆盖未合并）、默认值与兜底（默认值谁定的、旧数据落哪档、兜底掩盖已知上限还是未知失败）。这三类在改动本身自洽时最容易漏，`code-design` 原有的归属/深度/接缝/边界尺子扫不到。
- 改动：`tools/retro-failure-modes.md` — 新建一次性 retro，读全部 21 条 issue + 11 条 decision，产出证据来源分布、八族失效分类、审查装置的回归率、评测装置的 8 条操作纪律。**不进发布链路、不进技能包。**
- 回收：与 billion-context 对照后未采纳的五项（版本优先 triage、回归钉账本、放行判据表、门控双向断言、规则挂锚），理由记在 retro 第六节，避免下次重复评估。
- 验证：`python3 tools/check-skill-repository.py` 通过。`tools/` 不随技能分发，retro 不需要被引用。
- byissue：无 spec 漂移——Review 段的归属文件就是 `code-design.md`，`spec/index.md` 不重述 reference 内容。

## retro 产出的两条主要结论

1. **A/B/C 三族（写了但不执行、契约沉默处借用相邻概念、同一契约多处表述）合计 10/21，占 48%**，而它们的共同点是不在文本字面里——通读文本和 checker 结构性地看不见它们。这解释了 A 族在 001→008→011→018 复发四次：每次修法都是「改成祈使句」，而 018 证明祈使句绑错时点同样不触发。
2. **对抗性审查修完还得再审**：34 个 P 级缺陷里 4 个 P0 全部由被审改动制造（预期内），但其中 2 个 P0 是修复动作自己生产的，第五到第八轮每轮都在修上一轮修复引入的 P1。精确匹配类改动不适合靠迭代修复收敛，正确做法是先枚举形态做夹具再选判据。

## 对抗性审查后修复（P1 × 1、P2 × 2）

- **P1 探针 1 重抄了 `debug.md`「根因外推」的清单。** 原文五项里「重入」「旧快照被无条件写回」「先查后改之间的窗口」与 `debug.md:32` 逐字或近似相同，而审代码姿态读不到那份完整清单（`SKILL.md` 只把 debug 挂在「修 bug 升级慢路径」）。后果是双向的：按清单核对会漏掉回调/异步/锁，而以后给 `debug.md` 补一条，review 副本不会跟着变。改为「状态域危险的完整清单归 [debug](debug.md)『根因外推』，按它过一遍」——仓库里 `complain.md`、`design.md` 已有四处同款链接式先例，这处是第五处且是唯一重抄的一份。
- **P2 新增强制步骤没接进本段唯一的执行序列。** `### 步骤` 第 3 条只写「过尺子」，探针写在步骤之外，模型按 1→2→3→4 执行会直接跳过。第 3 条补「再过三类盲区探针」。
- **P2 `AGENTS.md` 写入边界四个落点、两个指针目标（先于本次存在）。** `note.md` 重述了 `SKILL.md` 的规则与理由，`maketools.md` 与 `close.md` 写「不写 AGENTS.md / CLAUDE.md（见 note.md）」指到 note 而非权威的 `SKILL.md`。`note.md` 改为只留姿态增量（写进 notes 是终点 + 提示用户自己加索引），另两处删重述子句只留指针。

审查的三条「已查、判定不构成重复」也记下，避免下次重开：探针 3 与 `economy.md` 有界简化（后者已链接、问的是两端）；探针 2 与 `quality.md` 九特征（特征是词汇，不是规则）；探针 2 与探针 3 之间（可见性 vs 兜底政策，修法不同）。

顺手发现：`tools/posture-scenarios.md` 的 8 条装置纪律散落在 `byissue/issues/004-x-posture-routing-regression-tests.md` 正文里，下次做评测得先翻一遍历史事项才看得到。不在本次范围。
