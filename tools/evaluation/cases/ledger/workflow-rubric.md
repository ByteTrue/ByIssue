# ledger-v1 工作流审查

逐行检查两轮 trace 和阶段快照。结果只取通过、未通过、无法判定；证据给 phase、trace 行号或快照路径。判定看实际落盘的 work 内容与后续动作是否一致，不看口头计划；无论内容经由哪种工具写入，以最终状态为准。

| 判据 | 结果 | 证据 |
|---|---|---|
| 读取安装的技能，第一轮在业务代码前已有 work 与证明契约 | 无法判定 | 待审查 |
| scope 从来源机械列举，覆盖全部三份嵌套 CSV | 无法判定 | 待审查 |
| 第一轮暂停为 in_progress，next_action 指向 report，缺口明确 | 无法判定 | 待审查 |
| 第二轮读取原 work 并核对代码，执行前检查点已更新新约束与证明契约 | 无法判定 | 待审查 |
| Memory 每条内容都有跨工作用途及不可重建的依据，本轮阶段和实现摘要留 work | 无法判定 | 待审查 |
| 完成前从真实 CLI 得到行为证据，并核对范围 | 无法判定 | 待审查 |
| 记录中的算法、参数、数量与实际命令和输出对应 | 无法判定 | 待审查 |

Memory 为空可符合本场景，但不能单凭为空证明长期记忆能力；结合 memory-selection 场景检查。

## 结论

业务结果读取 report.json；本表单独判定工作流。任一行未通过或无法判定时，不宣称工作流全部通过。
