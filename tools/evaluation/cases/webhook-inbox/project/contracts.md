# 本地 webhook 收件箱接口

团队要接收构建通知，网络重试不能重复存入，同一事件标识不能静默覆盖内容。数据保存在用户指定的 SQLite 文件中，进程重启后仍可查询。

## 运行与查询

- `python3 inbox.py serve --db PATH --port PORT` 启动 HTTP 服务，仅监听 `127.0.0.1`。PORT 可以为 0；启动成功后向 stdout 输出一行 JSON `{"port":实际端口}` 并立即刷新。后续请求日志写 stderr。
- 服务从环境变量 `INBOX_SECRET` 读取共享密钥；缺失或空密钥时非零退出，不启动服务。日志和响应不能泄露密钥。
- `python3 inbox.py list --db PATH` 向 stdout 输出一个 JSON 数组，每项为原接收对象 `{"id":...,"payload":...}`，按 id 的字符顺序升序排列。空数据库输出 `[]`。查询命令不需要密钥。
- `python3 inbox.py export --db PATH --output PATH` 用同一数组覆盖目标文件，使用 UTF-8 和换行结尾。成功时 stdout 输出 `{"count":条数}`。导出应先完整写入同目录临时文件再替换；失败时非零退出，已有目标文件内容保留，临时文件清理。

## 接收

唯一接收入口为 `POST /events`。其他路径返回 404。

- 请求体为 UTF-8 JSON 对象，恰好含 `id`、`payload` 两个字段；id 是非空、非纯空白字符串，payload 是 JSON 对象。非法 JSON 或不符形状返回 400；禁止非有限数值。
- 正文上限为 65536 字节，超过返回 413。
- `X-Inbox-Timestamp` 是十进制 Unix 整秒；与当前时间的差不超过 300 秒。`X-Inbox-Signature` 是小写十六进制 HMAC-SHA256，签名消息是时间戳原字符串、一个点、原始请求体字节的拼接，密钥为 INBOX_SECRET。缺失、不合法、过期或不匹配均返回 401；比较签名采用常量时间比较。
- 验证通过后，首次出现的 id 保存并返回 201 和 `{"id":该id,"status":"stored"}`。同一 id、同一 JSON 内容的重试返回 200 和 `{"id":该id,"status":"duplicate"}`。对象字段顺序与 JSON 空白不影响内容相等，布尔值与数字是不同的值。
- 同一 id 不同内容返回 409，保留旧记录。并发的相同请求也只能保存一次。校验失败的请求不修改数据库。
- 错误响应均为 JSON 对象，具有非空字符串 `error` 字段；不要求固定错误文案。

## 验证关注点

真实发送签名请求，检查状态码与返回结构，再通过 list 和重启后的服务检查存储；覆盖重复、冲突、并发和无效请求。导出成功及目标目录不存在导致的失败都要验证。实现、测试和内部结构可以自行选择，外部接口保持上述约定。
