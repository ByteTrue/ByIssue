这个 BySpace 专用评测分支缺失了“计划任务与 heartbeat”的后端实现、CLI/RPC 处理和前端列表/表单。现有协议、客户端、路由、调用方、公开文档和回归测试仍在。请按现有产品接口恢复完整功能，保持其他功能兼容。这里没有旧版 bi 工作记录，请用当前安装的 v2 工作流管理这项工作。

需求：

一、计划任务与 heartbeat
- 计划任务每次启动一个新 agent；heartbeat 向已有 agent 的同一会话发提示。支持创建、列表、查看、运行日志、更新、暂停、恢复、手动执行和删除，按现有协议区分两类目标的可用操作。
- 保留现有 JSON 字段和错误响应约定，兼容已持久化的记录。修改遵守 patch 语义：未提供保持原值，显式 null 清除可空字段；archiveOnFinish 的 false 必须保留，不能当成缺省。
- 对无效 prompt、target、provider、cwd、次数上限、到期时间与 cadence 给出明确错误，失败不能损坏已有记录。

二、时间与调度
- 支持五字段 cron 的列表、范围、步长和 IANA 时区；按本项目语义，日与星期字段同时满足。处理日历边界与夏令时，返回严格晚于给定时刻的下一次运行；不可能的时间表达式应有界失败。
- 保留既有 everyMs 记录的兼容性。CLI 接受裸分钟数和带单位的时长；--every 仅接受能被五字段 cron 忠实表达的周期，例如 15m、1h，拒绝 7m 或秒级周期并说明原因。
- 默认和 runOnCreate/run-now 的关系遵循现有调用约定。一次 tick 只启动到期任务，同一任务不能重叠执行；下一次运行基于计划时刻而非完成时刻。普通 tick 延迟时也跳过积压：本轮每个到期任务只运行一次，下一次取当前时刻之后的时间槽；旧 everyMs 保持原计划的间隔网格。
- 暂停后不再自动触发，恢复正确计算下一次运行。maxRuns、expiresAt、目标失效会使任务结束；普通执行失败留日志并按规则继续。手动执行不挪动原 cadence，次数核算保持现有语义。
- 重启恢复：把中断的 running 记录标为失败并记录原因，按正常结束时的归档约定处理运行工作区；尚未成功创建 agent 的残留工作区仍应清理。跳过错过的时间槽，不把积压任务全部补跑。失去目标的 heartbeat 应完成。

三、执行与持久化
- 计划任务使用独立运行工作区，不能归档用户原本的项目工作区。正确传递 provider、model、mode、thinking、title、providerOptions、featureValues 与 systemPrompt。
- 创建工作区或 agent 后立即记入运行记录，成功/失败都有输出或错误；默认归档运行工作区，显式 archiveOnFinish=false 时保留。启动 provider 失败也要清理该次工作区。
- heartbeat 发出的消息包含任务身份、运行身份和原 prompt；agent 被归档或删除后不再持续触发。
- 原子持久化、并发互斥、稳定的列表与日志顺序、损坏记录隔离，以及删除/替换/重启时的状态处理均需要验证。按现有接口保留同名替换等行为。

四、CLI 与 RPC
- 恢复 byspace schedule / heartbeat 的完整命令链，包括 provider/model 解析、目标选择、时区、到期、次数上限、JSON 输出和清除可空字段的更新参数。
- 兼容接口补充：schedule update 用 --no-max-runs、--no-expires-in 清除限制，更新必须真正保存；空 --expires-in= 应明确处理或拒绝，不能 panic。create --json 输出任务对象；update --json、inspect、pause、resume 输出含 schedule 字段的响应对象。heartbeat create 默认从 BYSPACE_AGENT_ID 取当前 agent，不能要求再传 --target。
- schedule update [flags] <id> [新提示词...] 接受 id 后的位置文本作为新 prompt，并与清除限制等参数在同次更新中保存；省略新提示词时保持旧值。
- 错误参数在连接前能判断的应先报错；接口、响应字段与已有客户端兼容。不能用空实现、总是成功的返回值或删除调用方来绕过缺失功能。

五、前端
