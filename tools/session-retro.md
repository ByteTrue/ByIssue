# 真实会话复盘

把一次真实使用 `bi` 的会话变成对技能包的修改候选。复盘只收能在未来改变判断、动作或证据要求的经验。

## 什么时候跑

用户纠正过 `bi` 的行为，或结果显示它本应做出另一项可验证动作时再复盘。一次性的环境问题和已经按规则完成的会话不进入候选。

## 怎么跑

1. 读取这次会话实际使用的 work、代码、测试和运行证据。会话里的自述只作为线索，回到真实文件核对。
2. 按四种行动重建当时的主行动，找出哪个时点缺少规则、规则没有绑定到动作，或检查没有走到真实入口。
3. 把候选归到一个唯一位置：`SKILL.md` 的共同规则、一个核心 reference、一个按需原则、维护侧 checker，或用户项目的 `memory/`。
4. 查重已有规则和同主题 Memory。重复内容改归属或修正原文，不新增第二份契约。
5. 只把能改变未来决策的候选写入修改列表，随后按仓库的发布检查验证。

## 筛选标准

| 判据 | 通过条件 |
|---|---|
| 持久 | 代码形状、版本和会话细节变化后仍成立 |
| 改变决策 | 未来 Agent 会因此改变动作或判断 |
| 单一归属 | 能指出唯一的权威文件 |
| 可验证 | 能由代码、检查或真实入口观察结果 |
| 不重复 | 现有规则无法清楚挡住这次失败 |

复盘的结论先写证据和推荐修法，再修改技能。修改后重新阅读相关 work 入口和 reference，确认没有形成第二套表述。
