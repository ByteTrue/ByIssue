# 提示词对抗性审查

`skills/bi/` 是**散文即逻辑**：改一句 reference 等于改一次代码路径。checker 只挡路径漂移，`posture-scenarios.md` 只测姿态路由，都不审**文本本身会不会让模型判断错**。这份表补那一层。

## 怎么跑

**改过 `skills/bi/` 任何字节之后、发布之前，起一个 subagent 跑一轮。** 不要自己审自己：参与过这次改动的上下文知道答案，会为自己的写法辩护。

- `agent: reviewer`，`maxTurns` 至少 60，**并且显式给 `timeoutMs`（建议 2700000，即 45 分钟）**。默认的 20 分钟会先于轮数生效，超时返回的是 `paused`——一份**中途截断**的报告看起来与「查完了，很干净」一模一样，而本文件又要求每类都给出结论。**超时截断的报告作废**，续跑或重开，不要当成一轮完整审查。
- **墙钟才是真正的约束，不是轮数**：审查者一轮里批量跑多条命令时，45 分钟可能只走 18 轮。所以任务书里要**预先给出预算分配**（哪几类深查、哪几类快扫、已测过的输入类不要再测），并且让它**每查完一类立刻落盘**——超时后能用的只有草稿，会话日志里的 thinking 只能算抢救，不算一轮结论。
- `task` 用本文件「给审查者的任务」一节，外加本次改动的位置（`git diff --stat`）。
- 给它**完整工具**，它必须能跑 grep、读文件、跑脚本；**不许它改任何文件**。
- 审查对象是**全部** `skills/bi/`，不是只看 diff——同类问题往往在没动过的文件里。**本文件自身也在范围内**：它同样是给模型读的散文，写错一句（比如给出一条不可能的举证要求）会让每一轮审查都跑偏。
- **先扫后深挖**：先按七类各跑一遍最小命令、形成全量结论，再对可疑项深挖；不要在一处精益求精到最后没时间出报告（超时截断＝作废）。
- **边查边落盘**：让审查者**先建草稿再开始查**，每查完一类就追加该类结论，最后一并把「## 结论」写进去（任务模板里给了具体命令）。**必须明确两件事**，否则它不会做：一是「仓库内文件不许动，但 `/tmp` 的草稿是例外、且必须写」（只说「唯一允许你写的文件」会被误读成「最好别写」），二是**给可直接复制的 bash 命令**，不要只描述要求。实测：第三轮审查写了这条要求却没给命令，审查者一个字节都没落盘，超时后只能从会话日志里抢救结论。有草稿时超时只是截断，结论还在，续跑只需读草稿排版。
- **路径以仓库 `skills/bi/` 为准**。子 agent 若自行加载 bi 技能，加载到的是部署副本 `~/.agents/skills/bi/`；本步骤在 rsync **之前**，两者可能不一致，读文本要读仓库里的那份。

**审查者给的修法不是结论，是待验的候选。** 收到修法先自己搭夹具跑一遍再落笔：本仓库出现过三次「审查给的修法本身不完整」——补上的边界字符类漏了它没想到的形态，等于把缺陷换成另一个缺陷。父会话修完还要**回读文件**确认改到位，记录里写「已改为 X」而文件里不是 X，是同一类错误里最贵的一种。

**发现即修，不分优先级。** 本项目不接受「P2 留待下次」：一条已确认的错误陈述会在之后每一次会话里被读到。审查者按危害排序，但每一项都要修。

**「不确定」不是结论，也不许凑数。** 每条发现必须给 `文件:行号` + 原文引用 + 证据；证据有两种合法形态：

- **可复现命令**（路径、形态、正则、链接这类机械事实）——贴出命令与输出。
- **行为评测**（「模型会不会这么做」这类判断）——结论只能来自 `tools/posture-scenarios.md` 或子 agent 评测，贴出场景与观测到的调用序列。**审查者自己跑不了评测**：reviewer 子代理的工具集只有 `read` 与 `bash`，没有 subagent。缺行为证据时标「待行为评测」并写清需要哪个夹具、断言什么，由发起审查的父会话并行提供；不要花时间搜索工具去确认这件事。

**没有证据时写「待核实」并说明缺哪次评测**，不要用「这句话存在」冒充「这句话挡了假想默认」——那正是本类要防的假发现。『发现即修』只适用于已经证实的项；待核实项不改，改为回报。

## 判据归谁

- **工作流文档只写给现在用它的人** → 仓库根 `AGENTS.md`
- **否定式表述要挣得它的注意力成本**（粉色大象）→ `byissue/spec/index.md`，清理记录见 `byissue/decisions/010-negative-statements-must-earn-their-attention-cost.md`
- **单一归属、技能自足、只分发 `skills/bi/`** → `byissue/spec/index.md`

审查者读这三处，不重述判据。

## 给审查者的任务

> 你是对抗性审查者。审查一套会被分发到**用户所有项目**的 Agent Skill：`skills/bi/`（唯一被分发的部分）。产物契约里**散文就是逻辑**——改一句 reference 等于改一次代码路径，所以你要找的是**会让模型判断错误的缺陷**，不是文风意见。
>
> 先读仓库根 `AGENTS.md`、`byissue/spec/index.md`「改这个仓库要守什么」、`byissue/decisions/010-*`。那是判据，不要另立一套。
>
> **七类必查，每类给结论，查完没问题的明说「已查，未发现」并附命令：**
>
> 1. **演变史/自传**：解释「以前是什么」「取代了什么」「哪次改的」「为什么这么改」「已经删掉」的句子；版本号、日期、issue/决策编号出现在**规则正文**；对新读者无意义的自我指涉（「本次」「此次清理」）。区分**业务语义**（「复杂度涨到不再适合快改」「这块以前栽过吗」）与**工作流自传**——前者留，后者是缺陷。
> 2. **粉色大象**：逐条列出规则级否定式表述，标注 X 是**真实强默认**还是**假想默认**。挡模型本来不会做的事 = 缺陷。
> 3. **路径与命名契约自洽**：所有写出的路径形状彼此一致，且与 `SKILL.md` 路径表一致。**特别核对有没有编造的不存在的形态**——这类错误最贵，因为它看起来像真的。状态字母、占位符词汇、日期前缀的覆盖范围都要核。
> 4. **单一归属**：同一契约是否在两处被重述且可能漂移；`SKILL.md` 已有的规则是否在 reference 里被重复（`SKILL.md` 常驻上下文，reference 按需加载）。
> 5. **自足性**：`skills/bi/` 里的**每一处路径**是否都能在用户项目里存在。注意两条隐藏通道：`init_byissue.py` 会把 `templates/entities/` 的内容**逐字写进用户项目**，模板里的技能包路径会跟着落地；`tools/`、`byissue/`、`CHANGELOG`、`VERSION`、`WHY BYISSUE.md` 都不分发。
> 6. **可执行性**：描述句（规范产物归属）是否被当成动作期待；祈使句是否绑对了时点（本项目已知「只有祈使句会被执行」）。
> 7. **交叉引用完整**：以 `python3 tools/check-skill-repository.py` 的输出为准（已覆盖双向链接可达、模板自足性、姿态与 frontmatter `description` 双向触发词认领、本仓事项引用），不要重做它已经断言的事。
>
> **每条发现给三样东西**：`文件:行号`、**原文引用**、它会在**哪个具体场景**下导致什么错误产物。没有场景的错误不要报。
>
> **边查边落盘（第一条命令就该做）：** 先跑
>
> ```bash
> printf '# prompt review 草稿\n' > /tmp/prompt-review-roundN.md
> ```
>
> 之后**每查完一类，立刻用 `bash` 追加该类结论**（发现 + 命令 + 输出摘要），例如
>
> ```bash
> cat >> /tmp/prompt-review-roundN.md <<'EOF'
> ## 第 3 类 路径与命名契约
> - 已查，未发现
> - 命令: ...
> EOF
> ```
>
> **最后把「## 结论」整段也追加进去。** 报告以草稿为准。**仓库内任何文件都不许动；草稿是唯一例外，且必须写**——超时上限一到，只有已落盘的内容能用上；前两轮审查都因把报告留到最后而全部丢失，第三轮又因没落盘只能从会话日志里抢救。
>
> **你没有 subagent 工具，跑不了行为评测**（工具集只有 `read` 与 `bash`，别去找）。需要行为证据的项标「待行为评测」，写清夹具与断言，由发起方提供。
>
> **不要修任何文件。** 最后给总体判定：可以分发 / 修掉发现后可以分发 / 不可。
>
> 事实自己跑命令核，不要推测。给修法时写清具体行与替换文本，不要只说「建议改写」；**修法自己先在夹具上跑过再给**——判据类修法在纸上看着对、跑起来错的情况很常见，给一条没验过的修法比不给更贵。

## 与另外两个检查的分工

| 检查 | 挡什么 | 什么时候 |
|---|---|---|
| `tools/check-skill-repository.py` | 机械：版本、包布局、路径可达、姿态表结构、`byissue/` 内的悬挂引用 | 每次改完 |
| `tools/posture-scenarios.md` | 语义：姿态路由是否选对、必读是否加载 | 动过姿态表或任一姿态必读文件后 |
| 本文件 | 文本：规则本身会不会让模型判断错 | 改过 `skills/bi/` 任何字节后 |
