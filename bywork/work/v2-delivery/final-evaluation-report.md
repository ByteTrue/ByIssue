## 评测方法

### 任务构造

大型重建任务 case-v5：在 BySpace 仓库固定提交上删除「计划任务与 heartbeat」成熟功能的 6422 行实现（Go 后端、CLI/RPC、React 前端），保留协议、客户端、路由、调用方、公开文档与回归测试作为兼容性依据。删减副本源码树哈希固定为 `4bc49f17b3673fb794df6bdc72ed08e1d723f91c`，全部轮次一致。原实现与独立验收留在被测项目之外，模型读不到答案。

独立验收共 12 组：Go overlay 注入的公开 API/CLI 探针（重启保留、半小时 DST、日历边界、持久化 patch、运行恢复、CLI/RPC 响应形状等）、定向回归（含 `-race`）、构建、vet、前端单元/类型/构建、两个 Playwright spec。验收由父进程运行，程序与期望值不传入被测模型。

三个短场景各测一件事：ledger 两阶段测跨会话接续与按要求暂停；memory-selection 测 Memory 筛选（正向对照：完全不写 Memory 也算失败）；heldout webhook-inbox 是未参与任何技能改写的新业务任务，测泛化。

### 执行纪律

- 每轮规则改动先冻结技能快照（逐文件 SHA-256）并断言改动文件集合，再运行。
- 每轮使用新运行目录；失败目录保留不覆盖，首次失败单独留档。
- 运行器核对实际模型、会话唯一性、安装副本一致、既有测试文件是否被改。
- 自然压缩由宿主按 400k 阈值触发，不预设次数；压缩事件与持久摘要逐项核对。

### 判定

业务与工作流分开判。业务门 = 12 组独立验收全零且 `changed_original_tests` 为空。

工作流门经历过一次判据转向：

- 旧判据（候选三至二十一）：压缩后第一项工具调用必须读取 work 检查点，按 trace 工具名审查。
- 转向依据：候选二十一第二轮证明恢复指令逐字保留在压缩摘要中，模型仍不遵守；且该门自候选十四以来没有拦截过任何真实事故——真实事故（批量填绿、非法状态、丢缺口）由完成门和逐行回写规则拦截。经用户确认改为结果判据。
- 新判据（候选二十二起）：接续后的动作与检查点一致——做对当前该做的事、状态诚实、缺口不丢、无假完成；按 trace 与最终 work 审查。

「单次大型运行全绿」的交付门也经用户判断替换为 A/B 通过率协议。依据：候选二十六至二十九的失败点在各代码区域随机轮换（每轮新增规则都生效，但此前通过的项会翻车），继续逐轮补规则追逐的是模型方差。A/B 协议：同一任务、模型、thinking 与验收，A 臂不安装技能（任务文本仅去掉工作流措辞，其余与冻结输入逐字节一致），B 臂安装技能，交替顺序各跑三次，比较业务通过率与范围。

## 规则演变摘要

30 个候选，每轮改动由一个具体失败驱动。最终存活的规则与它挡住的事故：

| 存活规则 | 挡住的真实事故 |
|---|---|
| 接续先读检查点、逐行实现与回写 | 基线轮批量填绿、口头声明 complete |
| 安装输入只读 | 候选四对安装技能跑 formatter，改坏被测技能 |
| 既有测试只读，新增回归放新文件 | 候选五、十六改既有测试适配实现 |
| 完成门：status 合法值、缺口恰空、失败逐项点名 | 候选六、十五、二十七与 A/B bi-01/02 写 done/completed 或假完成 |
| 公开入口保存原始输出；失败就是失败 | 候选七 `--json` 输出人类文本；靠日志或放宽断言填绿 |
| 持久化布局沿调用方/文档/夹具对账，新进程复验 | 候选九、十把存储根当记录目录，重启后记录全丢 |
| 共享路径改前留基线、改后同入口逐项比较 | 候选十一、十二修一处坏另一处 |
| 可选策略分支矩阵；分支×生命周期相交逐组合验证 | 候选十三、十七、二十六、二十九 archiveOnFinish=false 的 workspace 被重启归档 |
| 默认响应形状以契约为准，不从新实现推断 | 候选十五、十七 CLI 文本冒充 JSON 响应 |
| 证据按行落到可定位断言，汇总绿灯不算行证据 | 候选二十七用「57 tests 通过」填证明行，该行无断言覆盖 |
| 并发行为用竞态检测强度验证 | 候选二十八 DATA RACE 在仓库惯例命令下不可见 |

删除的仪式：压缩首读门历经七轮堆叠（候选十五入口硬闸门、十七固定口令、十九工具名语义、二十 next_action 前缀、二十一 must_hold 前缀），最终整体删除（候选二十二），只留「接续时先读检查点、动作与检查点一致」。删除依据：指令逐字保留在压缩摘要中模型仍不遵守（候选二十一第二轮）；该门自候选十四后未拦截任何真实事故。

提示词质量四原则（用户在迭代中确立，已写入 `memory/project.md` 与 `memory/evaluation.md`）：

1. 极简优雅：提示词引导模型完成流程 1234；工具选择与操作顺序放权给模型。
2. 注意力成本：模型本来就会做对的事不写，肯定式表述同样受此约束。
3. 方法论而非工具绑定：写「什么算证明」（跨进程观察、原始输出、竞态检测强度），不写「必须先用哪个工具」。
4. 否定式表述须对应真实作弊路径：粉色大象审查 34 处否定式逐条通过，每处对应模型实际犯过的替代路径并指明正确动作。

效果：SKILL.md 从堆叠峰值 178 行减至 102 行，比本轮起点（150 行）少 48 行。瘦身后模型遵循度反而上升——A/B 与候选三十两轮在 thinking max 下全部通过。
