# 标准评测与规则修订结果

最终修订在本轮两个场景中通过业务验收和已列工作流判据。旧版复现了检查点晚写与 Memory 污染；修订过程中另外发现并修复了长期结论越界、待做接口契约遗漏。所有失败运行保留。

执行方法见[标准流程](../../../../tools/evaluation/README.md)。本轮使用 pi 1.5.2、`bytetrueapi/deepseek/deepseek-flash`、medium thinking。基线来自提交 `280daab` 的技能快照；各版使用相同场景提示、原始数据、独立验收和环境提示，摘要已逐项比对。每个 ledger 运行包含两个新会话，Memory 场景为一个新会话。

第二版中，Agent 自己的测试全部通过，但父进程验收因 report 不是 JSON 而失败。该实际错误产物已进入运行器离线回归，证明独立验收能挡住“实现与自写测试一起偏离用户契约”。

## 修订依据

- [第一次修订差异](candidate-skill.patch)：把新单元和新要求绑定到独立 work 写入，Memory 写前判断跨工作用途与不可重建性，证据标签核对实际命令。
- [第二次修订差异](final-skill.patch)：长期结论只覆盖已确认范围，推演策略保留为候选。
- [第三次修订差异](revision-3-skill.patch)：待做行为也完整保存用户指定的输入输出格式与错误边界，暂停前按原需求核对；接续缺项时回查或提问。

差异均相对于旧版技能。`candidate-*` 表示第一次修订，`final-memory` 和 `final-skill.patch` 是第二次修订当时的运行命名；当前技能由 `revision-3-*` 记录对应。安装副本与当前 `skills/bw/` 的比较通过。

## 证据与边界

每个运行目录保留 `review.md`、report.json、各阶段的工具 trace、提示、独立验收输出与项目快照。快照中的 Markdown 使用 `.md.txt` 后缀，避免成为本仓库的活动工作文档。临时路径归一化为占位符；原始思考流和会话文件留在临时运行目录。

工作流结论以各目录的 review.md 为准。历史 report.json 中的“待审查”字段是采集时的默认值；当前运行器只保存审查文件指针，不复制语义结论。

两个 ledger 修订仍写过固定 `/tmp` 路径标记，随后读回自身生成的临时路径。未观察到读取其他运行或验收材料，但这证明 TMPDIR 不能代替文件系统隔离。因此标准对照默认顺序运行，严格并发隔离需要宿主支持。

本轮没有无技能对照、同版多次重复、其他模型、大型代码库或真实上下文压缩。结果支持本场景修复，不支持“普遍提效”或“所有长任务都可靠”。
