# 账单迁移工具

## 目标与边界

完整目标是 `ledger.py` 提供两个 CLI。migrate 已实现并通过检查，本轮实现 report 并补上 `--min-cents`。

`python3 ledger.py migrate <source-dir> <output.json>`：

- 递归查找 source-dir 下所有 CSV，包括子目录。
- CSV 表头固定为 `id,customer,amount`。
- 输出 JSON 顶层是数组，按 id 排序，每行只有 `id`、`customer`、`amount_cents` 三个键。
- amount 是非负十进制金额，接受 `0`、`12`、`0.10`、`12.34` 这类普通写法，最多两位小数。拒绝负数、`NaN`、`Infinity`、指数格式和多于两位小数。金额换算必须精确，不使用浮点数。
- id 与 customer 不能为空。重复 id、错误表头或任一非法行都以非零码退出，错误写 stderr。
- 失败时原有 output.json 保持逐字节不变。
- 同一批输入重跑得到相同结果，原始 CSV 不变。

`python3 ledger.py report <output.json> [--customer <name>] [--min-cents <n>]`：

- 输出 JSON 对象到 stdout，只有 `count` 和 `total_cents` 两个整数键。
- 未指定 customer 时统计全部；指定时按完整名称精确匹配，不做大小写或前后缀放宽。
- `--min-cents` 默认 0，只统计 `amount_cents` 大于等于阈值的记录，可与 `--customer` 一起使用。
- `--min-cents` 只接受非负十进制整数写法，例如 `0`、`5`、`100001`。负数、小数、指数写法和非数字都以非零码退出，错误写 stderr，stdout 不输出 JSON。
- 没有匹配时 `count` 与 `total_cents` 均为 0。
- report 只读 `<output.json>`，不写任何文件，也不改动源 CSV。

## 已定方案与约束

- 实现放在项目根的 `ledger.py`，回归检查放在 `tests/test_ledger.py`，只用 unittest 和标准库。
- 金额用正则校验后按字符串拆整数部分和小数部分计算分，避免二进制浮点误差。
- 先完成全部读取与校验，再写同目录临时文件并用 `os.replace` 替换目标；任何错误发生在替换之前，因此旧输出不被改动。
- report 复用同一套 JSON 读取，过滤条件为 `amount_cents >= min_cents` 且 customer 完全相等；阈值解析用正则限定纯数字，再由 argparse 的 type 回调把非法值变成退出码 2。
- 原始数据是 `legacy/` 下的 3 个 CSV、7 行数据；逐项覆盖记录在 `scope.md`。

## 证据与决定

- migrate 已实现。report 按用户本轮要求补入 `--min-cents`，并保留原有 `--customer` 精确匹配与无匹配返回 0。
- report 输出到 stdout，因为命令行没有输出文件参数；这样也不触碰任何文件，满足只读要求。
- `--min-cents` 只接受纯数字写法，`+5`、` 5`、`1.0` 也会被拒绝。这是为避免 argparse 的隐式宽松解析而选的明确边界，用户要求的负数和非整数报错都在其中。
- 迁移范围从 `legacy/` 事实源枚举，命令和逐项状态见 `scope.md`。
- 回归检查命令：`python3 -m unittest discover -s tests -v`，Python 3.12.14 下 30 项全部通过（16 项 migrate、14 项 report）。
- 检查能挡住错误：migrate 侧已用临时副本验证（浮点换算、去掉重复检查、放宽小数位都会让测试失败）。report 侧本轮用四个故意做坏的副本复核，四个都让对应检查以断言失败结束：把阈值比较的 `>=` 改成 `>` 使边界检查失败；把 customer 比较改成大小写不敏感使精确匹配检查失败；把阈值正则改成允许负号使非法阈值检查失败；让 report 向输入文件追加内容使只读检查失败。
- 范围复核：完成前重新运行 `find legacy -type f -name '*.csv'`，仍为 3 个文件、7 行数据，三个 sha256 与 `scope.md` 记录一致。
