# 账单 CSV 迁移工具

## 目标与边界

`ledger.py` 提供两个真实 CLI。`migrate <source-dir> <output.json>` 递归迁移目录下所有 CSV，把 `id,customer,amount` 转成按 id 排序、只含 `id`、`customer`、`amount_cents` 的 JSON 数组。`report <output.json> [--customer <name>]` 汇总条数与总金额。

本轮只实现并验证 `migrate`。`report` 只保留目标和约束，留给下一会话。原始 CSV 只读，不提供修改或回写旧格式的命令。

## 已定方案与约束

- 金额用字符串解析成整数分。整数部分按十进制直接乘 100，小数部分补齐两位，不经过 `float`。
- 只接受 `0`、`12`、`0.10`、`12.34` 这类普通写法；拒绝负数、`NaN`、`Infinity`、指数格式、超过两位小数和空金额。
- 表头必须严格等于 `id,customer,amount`。空 id、空 customer、重复 id、字段数不符都算非法。
- 读取文件使用 `utf-8-sig` 忽略可选 BOM，CSV 解析使用标准库 `csv`，所有 CSV 读完后才写输出。
- 任何错误先汇总到 stderr，再以非零码退出。输出先写同目录临时文件，成功后 `os.replace` 覆盖目标，失败时清理临时文件并保留原 `output.json` 逐字节不变。
- 文件遍历顺序和 JSON 键顺序固定，保证同一批输入重跑得到相同字节。
- 回归检查放在 `tests/test_ledger_migrate.py`，从真实 CLI 子进程进入，运行命令为 `python3 -m unittest discover -s tests -v`。

## 证据与决定

- 回归检查命令：`python3 -m unittest discover -s tests -v`，本轮 13 个测试全部 OK。
- 初始数据见 `legacy/`，范围快照见同目录 `scope.md`；本轮按枚举命令覆盖 3 个文件。
- `report` 的精确匹配使用完整 customer 字符串，不做大小写或空白归一化。该决定来自需求原文“按完整名称精确匹配”。
- 空 id/customer 以 `strip()` 后为空判定，但输出保留原始值。该决定保证纯空白不会被当成有效标识。
