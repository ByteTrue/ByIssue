# 记忆与方向

这个行动维护会影响未来判断、但不能从当前代码直接重建的内容。它也负责把 ByIssue 接入项目和维护用户明确要求的长期方向。

## Memory

一条长期内容至少满足一个条件：

- 用户明确做出的长期决定；
- 当前环境确认过、未来仍会影响判断的外部事实；
- 值得未来重跑的证明或流程边界。

使用 `templates/memory.md`，默认把一个主题写成 `byissue/memory/{topic}.md`。正文说明结论、适用边界、依据类型、证据或复核方式、需要重访的条件。一个主题的后续事实更新原文件，不建立平行摘要。

代码、配置、测试和 git 能直接回答的实现事实留在它们原处。Memory 被当前用户决定或新证据推翻时，先更新记录并说明冲突，不静默保留两套结论。开始改变时按主题检索命中的 Memory，不遍历整个目录。

## Vision

用户要求整理产品方向、目标世界或跨变化的长期体验时，按 `templates/vision.md` 创建或更新 `byissue/vision/index.md`。Vision 保存用户旅程、能力方向、候选方案和明确边界；它不保存当前实现进度，也不代替当前 work 的证明。

方向改变先让用户确认。实现中发现目标无法成立时，把证据带回澄清，不把当前可行性判断静默写成新的 Vision。

## 接入与流程知识

用户说初始化或接入 ByIssue 时读取 [onboard](onboard.md)，运行 `scripts/init_byissue.py`，只补 `byissue/work/` 和 `byissue/memory/` 入口。Vision 目录按用户明确需要创建。

用户要记一个坑、外部事实或可复跑流程时，先查同主题 Memory，再更新或新增主题文件。实际可执行脚本留在项目代码或用户指定的位置，Memory 记录用途、输入输出和危险边界，不复制脚本实现。

## 出口

汇报写了或更新了哪条长期判断、它依据什么、未来何时复核，以及当前 work 是否需要同步。没有满足长期条件的内容留在当前对话或 work，不为了产生文件而产生文件。
