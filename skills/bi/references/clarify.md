# 澄清

澄清用于目标、术语、边界或取舍尚未确定的请求。它把模糊请求变成用户确认过的目标与约束，暂不把猜测写成实现安排。

## 行动

1. 先读项目里能回答事实的代码、配置、测试和已有入口。事实由 Agent 查，用户只回答选择。
2. 把当前未知拆成一棵决策树。使用 [grilling](grilling.md) 的轮次协议：每轮询问当前全部前沿，给出推荐，等用户回答，再重算下一轮。
3. 用户使用的词与代码或既有统一语言冲突时，按 [domain-modeling](domain-modeling.md) 当场指出；模糊词先提出精确候选，拿具体场景压边界。
4. 问题无法靠语言判断时，做最小草图或原型，让用户对具体东西作选择。UI 关系按 [ui-spec](ui-spec.md) 表达。
5. 前沿为空后，用一段话复述目标、范围、已定取舍和仍开放的项，等用户确认理解一致。

讨论本身通常留在当前会话。用户要求跨会话继续，或澄清过程已经成为需要管理的变化时，创建一个目标为“厘清某个问题”的 `work/{slug}/index.md`，把已确认内容写进去；工作进入实现后继续沿同一个 work。

## 记录边界

用户确认后，当前 work 的目标与约束可以落盘。长期有效的用户决定、外部观察或可复跑证明按 [memory-direction](memory-direction.md) 写入 `memory/`。代码能直接重建的内容留在代码和测试里。

## 出口

汇报已经确定什么、还缺什么、推荐的下一动作和用户需要决定的选项。用户尚未确认时停在澄清，不把未决方案当作已授权改变。
