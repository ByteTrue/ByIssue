# Project Spec

> **读者：** 要在这个项目里做判断的人——「这些词指什么、边界在哪、哪些方案已经排除过、哪些约束不能破」。  
> **自检（有则写，无则省略；标题用议题语言）：** 这个项目是什么（一两句） · 统一语言 · 做什么 / 不做什么 · 为何这样选、排除了什么 · 长期质量约束 · 稳定的界面约束（若有） · 阅读路径。  
> 目标全景在 `vision/`；拍板记录在 `decisions/`。

**准入判据：只写代码里重建不出来的东西。** 能力如何运作、架构地图、数据流、模块落点一律不写——那些读代码更准，写下来只会漂。判据与例外见 `references/spec.md`。
