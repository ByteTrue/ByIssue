# Project Spec

> **读者：** 第一次进入项目的开发者——「现在是什么、能做什么、从哪开始、边界在哪」。  
> **自检（有则写，无则省略；标题用议题语言）：** 项目是什么 · 当前重点 · 能力/场景地图 · 典型使用路径 · 当前界面（已成立时） · 架构落点 · 统一语言 · 阅读路径 · 做/不做 · 关键考量与长期质量约束 · 证据索引。  
> 主叙事是「怎么用这个项目完成事情」，不是代码目录。目标全景在 `vision/`，不写进这里。

每条阅读路径要带意图（关心什么 → 读哪里 → 读完能解决什么）。一个目录下出现多篇文档时，补该层 `index.md`（`templates/entities/spec-section-index.md`），不要散成平级文件。
