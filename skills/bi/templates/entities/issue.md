# [标题]

> **读者：** 跨会话接手的人——「要做成什么、别碰什么、现状与方案是否还成立、怎么验、关了要回写哪里」。  
> **自检（有则写，无则整段省略）：** 目标与范围 · 归属/来源 · 背景或当前证据 · 现状怎么工作 · 影响面 · 质量承诺 · 方案/设计（含有界简化：已知上限、升级触发、升级方向） · 风险与穿刺 · 验证 · 执行记录 · 关闭回写与结论。  
> bug 多答：预期/实际/最小场景/根因，验证时用原来的坏法再看一眼；refactor 多答：结构问题与必须保持的外部行为；chore 多答：操作步骤与危险边界。

几个容易写散的地方：范围写成「包含…；不包含…」；归属由文件位置表达，正文只按需链接相关 vision/spec；影响面分「必须改 / 需要验 / 仍未知」三层；执行记录在实现阶段追加，不预先留空壳。
