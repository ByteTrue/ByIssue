# [Epic 标题]

> **读者：** 在这条有界变化里对齐的人——「相对现状要改什么、现在怎么理解方案、哪些能推、哪些还悬着、关了合回哪里」。  
> **自检（有则写，内容少就合并成短文）：** 要改变什么 · 为何现在做 · 来源 Vision / 关联 project spec · 当前方案 · 架构与质量取舍 · 统一语言 · 可推进与暂不推进 · 未确认问题 · 关闭条件与合并候选 · 推进视图（issue / 直接切片）。  
> 禁止：任务流水账、第二份 plan/changes、复制 issue 实现设计、为凑自检留空章节。

写活规格而不是变化流水：只留仍然成立的方案叙述，说明架构上为何这样、不选什么、必须守住什么。来源 Vision 写清摘了什么、什么故意不在边界内。UI 若影响理解，标清当前/目标，用图说空间关系、文字说行为边界。

推进视图只记：可推进范围（含 epic 内直接推进的切片）、同目录 `issues/` 中的事项与各自解决什么、暂不推进或未确认的问题、关闭时要满足什么、合并回 project spec 的候选、关闭时要检查的 Vision 区域。
