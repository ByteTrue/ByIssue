# 记忆与方向

这个行动维护会影响未来判断、但不能从当前代码直接重建的内容。它也负责把 ByWork 接入项目和维护用户明确要求的长期方向。

## Memory

先逐条筛选，再决定是否写文件。候选内容需要同时回答：

1. **换一项工作后，它还会改变什么判断？** 仅为本次接续所需的目标、阶段、下一步、来源数量和验收结果留在 work。
2. **为什么不能直接从代码、配置、测试或 git 取得？** 实现步骤、当前接口形状和数据统计留在事实源；长期承诺的理由、外部限制与证明的适用边界才需要额外保存。

通过筛选后，记录以下内容之一：用户明确做出的长期决定、已确认的外部事实，或值得未来重跑的证明与流程边界。用户明确要求长期维持的兼容承诺可保留，记录承诺及依据；可重跑证明保存入口、适用条件和它能排除的错误，本轮运行结果仍留 work。

结论只覆盖依据已经确认的范围。由它推演出的实现策略、例外或相邻业务规则留作 work 中的候选；即使看起来合理，也不能写成用户已经确认的长期承诺。

使用 `templates/memory.md`，默认把一个主题写成 `bywork/memory/{topic}.md`。正文说明结论、适用边界、依据类型、证据或复核方式、需要重访的条件。只写当前成立的结论，不写变更叙事、会话视角或实现流水账。一个主题的后续事实更新原文件，不建立平行摘要。

保存前逐句删去混入的实现摘要和本轮交接信息；没有通过筛选的内容就保留空目录。Memory 被当前用户决定或新证据推翻时，在同一文件更新结论，并把旧结论及其理由保留为被否方案，防止旧路被当成新想法重提；不新开平行文件，也不只靠 git 保存旧理由。开始改变时按主题检索命中的 Memory，不遍历整个目录。

## Vision

用户要求整理产品方向、目标世界或跨变化的长期体验时，按 `templates/vision.md` 创建或更新 `bywork/vision/index.md`。Vision 保存用户旅程、能力方向、候选方案和明确边界；它不保存当前实现进度，也不代替当前 work 的证明。

方向改变先让用户确认。实现中发现目标无法成立时，把证据带回澄清，不把当前可行性判断静默写成新的 Vision。

## 接入与流程知识

用户说初始化或接入 ByWork 时读取 [onboard](onboard.md)，运行 `scripts/init_bywork.py`，只补 `bywork/work/` 和 `bywork/memory/` 入口。Vision 目录按用户明确需要创建。

用户要记一个坑、外部事实或可复跑流程时，先查同主题 Memory，再更新或新增主题文件。复盘与审计产物挂在被复盘的 work 下，并从其 index 链接；带待办和验收的新目标建自己的 work，已完成的 work 保持封存。实际可执行脚本留在项目代码或用户指定的位置，Memory 记录用途、输入输出和危险边界，不复制脚本实现。同类纠错第二次出现时，优先用责任归属、类型、lint、脚本或行为测试让错误无法再次发生，并用真实旧错误验证防线会失败；无法结构化时才保留文字规则。

## 出口

汇报写了或更新了哪条长期判断、它依据什么、未来何时复核，以及当前 work 是否需要同步。没有满足长期条件的内容留在当前对话或 work，不为了产生文件而产生文件。
